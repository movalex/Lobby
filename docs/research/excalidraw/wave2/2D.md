# Wave 2D: formats and templates on the new canvas

Owner 2D (docs/EXCALIDRAW-MIGRATION.md §7.2 "2D formats", §4.2 "Templates", §4.9, §3.7, §5.7). Branch
`engine/w2-2d` from `engine/excalidraw` 0f17569 (the wave-1 freeze). Engine `@excalidraw/*`
0.18.0-1118751. No lockfile, workspace or catalog change; no frozen file changed.

Owned files: `packages/templates/**`, `packages/board-ops/**`, `apps/web/src/dashboard/template-catalog.ts`
and their tests, plus the ported spec `e2e/excalidraw/templates-scenes.spec.ts`. The converter
(`packages/tldraw-import`) is spike B's and is only imported (by tests, and by callers through injection).

## 1. What was built

### 1.1 Templates: one content source, two emitters

The seven templates (Brainstorm, Mood board, Storyboard, Pitch outline, Retrospective, Production plan and
the Lobby tour) are written once against an engine-neutral builder and become a **plan**: frames, texts,
notes, boxes and arrows with their page geometry, in creation order (`packages/templates/src/builder.ts`,
`source.ts`, `templates/*.ts`, which import nothing but the builder). Two emitters read a plan:

| Entry point | For | Emits | Loads |
|---|---|---|---|
| `@draftroom/templates` (unchanged API) | the default (tldraw) build until wave 4 | tldraw 5.4.2 records (`src/tldraw.ts`) | `@tldraw/tlschema`, `@tldraw/utils`, `draftroomSchema` |
| `@draftroom/templates/scene` (new) | the new canvas: ported code (3b's template insert), servers | Excalidraw elements (`src/scene/emit.ts`) | canvas-schema `engine`, `elements`, `invariants`, `limits`; `@draftroom/board-ops/elements` |
| `@draftroom/templates/plan` (new) | the dashboard gallery (both builds) | plans and metadata | nothing (no engine, no tldraw) |

- **The tldraw output is unchanged.** Every template at two origins (one with `indexAbove`) was captured
  before the refactor and compared after it, ids and tldraw's jittered indices normalized: byte-identical.
  The tour's bold titles and elbow arrows became spec options (`titled`, `elbow`) instead of record edits.
- **The scene** (`instantiateSceneTemplate(id, {origin, indexAbove})` → `{elements, bounds, topLevelIds}`):
  frames (`name`, outline `#bbb`); free text wrapped by the engine's `wrapText` at the text's width,
  `autoResize: false`; sticky notes from canvas-schema `buildStickyNote` (the engine's note layout,
  `created: null`); rectangles, ellipses and diamonds with labels laid out by `layoutBoundText`; arrows bound
  with `FixedPointBinding`s (the anchor, or the centre as 0.5001, orbit mode) whose path is the room's own
  `resnapArrow`, repeated until it settles (a first re-snap can leave `width`/`height` one float ulp off);
  image slots and swatches carry `customData.lobby.slot = 'image'` / `swatch = 'color'`. Style names map as
  the converter maps stored boards (sizes, fonts, fills, the Lobby palette). Paint order is tldraw's (each
  frame, then its children; each container, then its label); indices are fresh keys above `indexAbove`;
  ids are fresh 21-character nanoid-style ids (`opts.newId` for deterministic callers); origin within
  ±900,000 so every element stays inside the ±1e6 coordinate limit. Every element passes the server's
  `checkElement` and the set `checkInvariants`, or the call throws `TemplateError('invalid-output')`.
- **Text metrics:** in a browser the engine measures with the canvas (build after Lobby's fonts have loaded,
  `document.fonts.ready`, or the wraps follow the fallback font); a Node caller installs the server
  table first (`installServerTextMetrics`, as apps/sync does at start-up). The e2e check (§3) shows the two
  agree within 0.1 px on every template.

### 1.2 `@draftroom/board-ops/elements` (new): board logic over elements

Plain elements in, plain elements out (canvas-schema `WireElement`); no tldraw in its import graph (a test
walks it). Every function tolerates malformed input.

| Export | Replaces (tldraw) | Notes |
|---|---|---|
| `elementText`, `kindOf`, `labelOf`, `lobbyValue`, `elementBounds`, `compareByIndex`, `lookupOf` | `extractSearchableText`, shape types, parent chains | a container's words are its bound label's `originalText` (found through `boundElements` and `containerId`, never id suffixes); a label reads as '' (its words are its container's); frames by `name`; images by `alt · file name` |
| `searchElements(elements, query, {limit})` → `{id, type, kind, text, snippet, score}` | `searchBoard` | the same matching and ranking (`text-match.ts`, shared with the tldraw search) |
| `elementsToCsv(elements)`, `colorCellOf` | `boardToCsv` | same header and cells (`csv-cell.ts`); `type` is Lobby's kind; `color` is the palette name (a note by its fill, anything else by its stroke) |
| `frameOutlineOf`, `presentationOrderOf` → `{id, name, bounds, presentIndex, skip}` | `frameOutline`, `presentationOrder` | `customData.lobby.present.index` first, then reading order; `skip` reported, left to the caller as today |
| `remapElements(elements, {offset, indexAbove, keepPresentIndex, newId, now})` | `remapIds` | fresh ids and group ids; references remapped or cut; the registry's duplicate rules for `customData.lobby`; `lobbyServer` never copied; labels right after their containers |
| `exportElementArchive(elements, doc, assets)`, `importElementArchive(file, {indexAbove, offset, limits})` | `exportBoardArchive`, `importBoardArchive` | archive v2 (`lobby-board`, §3.7); below |
| `importAnyBoardArchive(file, {convertV1, …})` (`@draftroom/board-ops/elements/v1`) | — | a v1 archive through the v1 checks, then the injected converter, then the v2 element steps |
| `noteElementsFromText(text, {origin, color, frameId, indexAbove})` | `notesFromText` | the same parser and grid (`bulk-parse.ts`); `buildStickyNote` notes in the hand-drawn face at 22 px |
| `elementFileRefs(elements)` → `{versionId, assetId}` | apps/api `referencedFiles` | image `fileId` (a PDF page to its version) and `customData.lobby.file` |
| `LOBBY_PALETTE`, `lobbyColor`, `noteColorName`, `strokeColorName` | canvas-ux `palette.ts`, tldraw theme colours | the converter's light values (a test keeps them equal) |
| `newElementId`, `randomInt31` | `createShapeId` | Web Crypto where present |

The tldraw modules are unchanged in behaviour; their engine-neutral helpers moved to `common.ts`,
`text-match.ts`, `csv-cell.ts`, `bulk-parse.ts` and `archive-common.ts` and are re-exported where they were.

**Archive v2.** Export keeps live elements in paint order and leaves identities out of the file:
`customData.lobbyServer` (authors, attribution, private-note authors), the registry's `strip` keys
(`plusOne:*`, `ai`, `privateFrame`) and `status`. The doc keeps what a client may write (`startView`,
`workshop`, `tagDef:*`), never `import`. Import: a strict envelope (`engine: 'excalidraw'`, element `schema`
not newer than ours), v1's JSON caps and prototype-key checks (40,000 elements), every element through
`checkElement` (unknown `customData` keys are refused, not dropped), refused and unknown types, duplicate
ids, doc keys through the doc registry, tags that must be defined in the doc, files not in the manifest
(warned), then `remapElements` (the board's slide order kept), coordinates re-checked after the offset,
and `checkInvariants`. Throws only `ArchiveError`; `warnings` carry counts, never content.

**v1 archives** keep today's v1 semantics (every page placed on one page, with the v1 warning), then the
converter's lossy codes are summarised in the warnings and returned as counts.

### 1.3 The dashboard gallery

`apps/web/src/dashboard/template-catalog.ts` previews templates from plans (`previewFromPlan`) and no
longer imports tldraw. Its output is identical to before (the whole catalog compared as JSON). Its chunk now
carries neither engine in either build.

## 2. Deliberate differences from the tldraw build

- **Plain text only** (plan §1 non-goals): a card's bold title is its plain first line on the new canvas.
- **No serif face**: the tour's "Display · serif" sample shows Excalifont and reads "Display · hand-drawn"
  there (a per-engine `scene` override in the plan; the converter maps serif to Nunito with `serif-font`).
- **Label ids** are fresh ids, not the converter's `<id>.t` suffixes (§3.6: readers follow `containerId`).
- Everything else is equal, field by field, to what the converter makes of the tldraw build (§3).

## 3. Evidence

- **Parity with the converter** (`packages/templates/src/scene/scene.test.ts`): one plan emitted on both
  engines with the same ids; the tldraw records converted by `packages/tldraw-import` `convertBoard` (its
  arrows re-snapped as the room does on the first write) and compared with the scene on type, geometry,
  colours, stroke, fonts, text, alignment, frame membership, lock, bindings, points and `customData.lobby`,
  labels matched through their containers: **no difference in any template** but the serif sample (3
  fields). The converter's semantic diff passes on shape mapping, frame membership, bounds, limits, anchors
  and files (its plain-text check looks labels up by suffix, so the same rule is checked by containerId).
  The Lobby tour is 167 elements, as the converted tour in B8.
- **Measured layout** (not tldraw's estimates): in every template no element overlaps another in its frame
  and every element stays in its frame; no note or box grows for its label; the tour's own checks
  (`scene/lobby-tour.test.ts`) pass on the elements.
- **The browser and the server** (`e2e/excalidraw/templates-scenes.spec.ts`): every scene is a fixed point of
  `restoreElements(…, {repairBindings, refreshDimensions})` in Chromium: nothing dropped or added, and only
  label and text widths (and a centred label's x) re-measured, by at most 0.0004 px in six templates and
  0.093 px in the tour (tolerance 0.5 px);
  every scene pushed as authored over a raw socket is accepted with **no server fix at all** (not even an
  index), reaches a second tab field for field, converges and survives a reload; a board exported as archive
  v2 and imported again is accepted and converges.
- Unit tests: `packages/templates` 399, `packages/board-ops` 217 (both packages' old tests unchanged and
  passing), `apps/web/src/dashboard` 57.

## 4. Findings and requests for other owners

- **CR-2D-1 (room, 2A / spike O1, `apps/sync/src/room/invariants.ts` `rejectPass`):** a label created in the
  same push as its **new** locked container is refused `LOCKED`. So the templates' labelled image slots,
  an imported board's locked cards and a pasted locked card lose their labels when a client creates them.
  Proposal: the lock rule applies to containers that were live before the push. The e2e spec keeps this as
  an expected failure; its other tests create those slots unlocked and lock them in the next push.
- **CR-2D-2 (canvas API, contracts + 2C, `LobbyTx`):** inserting prepared elements. `tx.create('note', …)`
  rebuilds the note (the spike's `buildNote`: `frameId`, `strokeColor`, the label's size and ink are lost)
  and `tx.create('text', …)` re-measures and re-positions a label, so a template, pasted notes or an imported
  board cannot be installed as authored. Proposal: `LobbyTx.insert(elements: readonly WireElement[]):
  string[]`, which installs server-valid elements as given (ids, `frameId`, bindings, labels, `customData`)
  and lets the engine core push them as creates; 3b's template insert and paste-as-notes need it.
- **2F (api):** archive and checkpoint v1 reads need `@draftroom/tldraw-import` as an api dependency (a
  lockfile edge, the lockfile owner's); `importAnyBoardArchive` takes the converter by injection
  (`(records) => convertBoard(records, {updatedAt, metrics})`). A Node caller that builds scenes or pasted
  notes installs the server text metrics first. `elementFileRefs` replaces `referencedFiles` for the export
  manifest.
- **2B (sync):** the search indexer's text (`apps/sync/src/http/board-text.ts`) on the new canvas is
  `searchableElementText`; apps/sync does not depend on `@draftroom/board-ops` yet (a lockfile edge).
- **Contracts:** `docs/EXCALIDRAW-CONTRACTS.md` §7.1's generated table lists `dashboard/template-catalog.ts`
  as 2D's one tldraw file; it no longer imports tldraw (one file fewer when the table is regenerated).
- **3b, 3e, 3d, 3h:** the element versions of search, CSV, frames, presentation order, remap and pasted notes
  are in `@draftroom/board-ops/elements`; templates in `@draftroom/templates/scene`.
