## How the probe works

The footer is drawn in `drawElementOnCanvas` for `stickynote` (`@excalidraw/element` dist/dev/index.js
13623-13633): 12 px Helvetica, right-aligned at `(width - 16, height - 14)` (`STICKY_NOTE_FOOTER`,
`@excalidraw/common` dist/dev/index.js 1811-1818), in the note's `strokeColor`. The spec reads Excalidraw's
static canvas (2D context) in that box, `[width-16-64, width-16+2] x [height-14-12, height-14+4]` scene
units mapped through `sceneCoordsToViewportCoords` and the device-pixel ratio, and counts "ink" pixels
whose RGB distance to the note's background is > 90 (sum of channel differences). It waits until the
note is painted (an inset corner pixel equals the background) and two consecutive reads agree. Light
theme only (the dark theme transforms colours; scaffold finding).

Each case has a control that must show the footer, so a 0 is evidence and not a blind probe:

| Case | Lobby | Control |
|---|---|---|
| 1. A note built by Lobby | `buildNote` (skeleton `created: null`) | the same note stamped `created: Date.now()` |
| 2. Ctrl+D | `/spike/host-lab`: click the note (off the label), `Control+d` (a delegated key) | the same on `?dup=off` (no Lobby stamp) |
| 3. Alt-drag | hold Alt, drag the note 300 px in 20 moves | the same on `?dup=off` |

## Engine behaviour (verified in the dist)

- `getStickyNoteDateLabel` returns null for `created === null` (element dist/dev/index.js 6855-6857), so
  `getStickyNoteFooter` returns null and nothing is drawn. Confirmed by pixels: 0 ink.
- `duplicateElement` sets `copy.updated` then `copy.created = copy.updated` on every copy (element
  17937-17939). With no host `onDuplicate`, the Ctrl+D and Alt-drag copies of a `created: null` note get
  a timestamp and paint "28 Sep" (control ink 171).
- `reconcileDuplicatedElements` merges what `onDuplicate` returns into the duplicate with
  `Object.assign` and bumps its version (element 18139-18163, the merge at 18157), so returning
  `{ ...el, created: null }` is enough. Both gestures go through it: Ctrl+D via actionDuplicateSelection
  (excalidraw dist/dev/index.js 3737), Alt-drag via `duplicateDraggedSelection` (28491, runOnDuplicate
  at 28547).
- **Finding: `convertToExcalidrawElements` overwrites `created` unless `regenerateIds: false`.** With the
  default, every skeleton gets `Object.assign(element, { id: randomId(), created })` (element 24527-24528),
  so a skeleton's `created: null` is lost. `_newElementBase` keeps an explicit `created` otherwise
  (`rest.created === void 0 ? timestamp : rest.created`, 16371). Lobby's `buildNote` therefore always
  passes `regenerateIds: false` with its own ids, and throws if the note comes back stamped.

## Deviations from the plan

- The Ctrl+D copy lands 10 px right and down of the original (`DEFAULT_GRID_SIZE / 2`, index.js 3730),
  so in the control run the copy's footer overlaps the ORIGINAL's probe box (the original, which has
  `created: null`, reads 42 ink pixels there in the Ctrl+D control only). The Lobby run shows 0 on both,
  and the assertions are on the copy.
- `currentItemStickynoteBackgroundColor` is not used: Lobby builds notes itself. "Lobby yellow" is a
  spike placeholder, `#ffd966` (`LOBBY_NOTE_YELLOW`); the plan names the colour but not its value.
