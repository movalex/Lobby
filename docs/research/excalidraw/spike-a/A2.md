## The cases

20 cases per run, deterministic (seeded PRNG, seed 0xA2). Each case:
1. A fresh note at (220, 160), 200 x 200: even cases with a label `Seed <i>`, odd cases with none.
2. The fake server's answer delay is set to 120-420 ms (random per case).
3. A real mouse click on the note body (off the label) selects it.
4. The user starts with **Enter** (cases 0,1,4,5,…; P1) or with a **printable key** (P2, type-to-edit),
   then types 6-14 more keys: letters (both cases), digits, punctuation, spaces, **Backspace** (8%),
   **Enter** (6%), with a per-case key delay of 0 ms or 30 ms (every third case), so some cases finish
   typing before the grant and some straddle it (keys buffered, then keys typed natively after the
   replay).
5. Expected text = Lobby's semantics: the caret goes to the END of the existing text (today's Lobby,
   `features/canvas-ux/keys.ts` A11Y-12 and COL-04: typing appends, never replaces), then every key in
   order (Backspace deletes the previous character, Enter inserts `\n`).
6. Pass per case: the synthetic Enter came after the grant; exactly 1 `lease.acquire`; the textarea value
   equals the expected text; after Escape the label element's `originalText` equals it (and, for the
   unlabelled notes, the label was created and bound to the note: `containerId` = note, listed in the
   note's `boundElements`); the lease is released.

## Engine behaviour (verified in the dist)

- The synthetic Enter reaches Excalidraw's container `onKeyDown` (a React handler, index.js 48684): the
  Enter branch (44152-44185) needs exactly one selected text or text container and calls
  `startTextEditing({ container })`. Excalidraw reads `this.state` synchronously, and
  `updateScene({ appState })` only schedules a React update (43825-43851), so Lobby selects the target
  inside `flushSync` first.
- `startTextEditing` creates the label when the note has none (44636-44690): a new text element with
  `text: ""`, `containerId` = the note, `baseFontSize` = `currentItemFontSize`, font =
  `currentItemFontFamily` (6, Nunito), inserted right after the container, and the container's
  `boundElements` gets it. Observed in all 10 unlabelled cases per run.
- The textarea is appended synchronously (25633) but focused in a `setTimeout` (bindBlurEvent,
  25545-25561), so keys typed between the Enter and the focus hit the container, not the textarea. Lobby
  keeps buffering until `document.activeElement` is the textarea.
- Excalidraw's own Enter opens with ALL the text selected (`autoSelect` -> `editable.select()`,
  25613-25614, on non-touch screens). Lobby moves the caret to the end before the replay (A11Y-12);
  without that, the first replayed key would wipe the note.

## Deviations from the plan

- The plan says "buffered keys replay in order"; it does not say where the caret is. The spike uses
  Lobby's existing semantics (caret at the end for Enter and type-to-edit). Proposed wording for §2.9.2:
  *"Granted: … replays the buffered keys at the end of the text (Lobby-initiated opens); an editor the
  guard caught keeps the caret or selection Excalidraw gave it."*
- There is no sync server in spike A: the grant comes from the local fake server
  (`lease/fakeServer.ts`), with the plan's message shapes and a strict schema.
