## What each role's script does

Scene: a note with a label, a rectangle with `link: https://example.com/lobby-doc`. Lobby's toolbar is on
(it sits outside the board wrapper; moving onto it is how the test leaves the board). Guests run with the
export policy "deny", commenters and viewers with "allow".

1. **Presence, no tool selected** (`activeTool` = selection): 30 mouse moves across the canvas. Lobby's
   listener must report samples whose last point equals the target scene point (within 1 px), at most
   ~20 Hz (asserted <= 26 Hz measured), while the probe `onPointerUpdate` stays at 0. Moving onto the
   toolbar must send `{ pointer: null, source: 'pointerleave' }`. Contrast (engine behaviour, not a pass
   condition): with a custom tool active, `onPointerUpdate` fires.
2. **Leaving a custom tool**: Excalidraw's `api.setActiveTool({ type: 'selection' })` directly (engine
   behaviour), then Lobby's `setTool('select')`; `setTool('hand')` must be refused.
3. **Pan and zoom**: wheel (pan), primary-button drag on empty canvas (pan), Ctrl+wheel (zoom), Ctrl+=
   and Ctrl+- (zoom in and out).
4. **Links**: a click on the linked rectangle must reach Lobby's `onLinkOpen` with the URL (the handler
   calls `preventDefault`); 0 popups; the page URL unchanged.
5. **Custom tools**: Lobby's comment tool (`custom`, `locked: true`): a click reaches Lobby's handler
   (`api.onPointerDown`/`onPointerUp`), no element changes.
6. **Keys**: 29 keys with the note selected programmatically (Delete, Backspace, arrows, Ctrl+D, Ctrl+A,
   Ctrl+Z/Shift+Z/Y, Ctrl+G, Enter, N, T, R, X, 2, Ctrl+S, Ctrl+Shift+S, Ctrl+O, Alt+Shift+C,
   Ctrl+Shift+E, Ctrl+X/C/V, Ctrl+Alt+C, Shift+H, Tab, ?, Escape). Each: no element version change, no
   change in 30 appState fields; overall 0 File System Access picker calls, 0 clipboard writes.
7. **Clipboard events**: synthetic `copy`, `cut` and `paste` (with `text/plain`) on the focused
   container: nothing written into the `DataTransfer`, nothing pasted, nothing cut. For guests, Lobby's
   copy listener must `preventDefault` (policy "deny").
8. **Drop**: synthetic `dragenter`/`dragover`/`drop` with a PNG file and text on the canvas: `dragover`
   and `drop` default-prevented (the browser would otherwise open the file), Lobby's upload handler not
   called for a read-only role, no element added.
9. Overall: 0 downloads, 0 dialogs, 0 file choosers, 0 page errors.

**Control (editor)**: the same synthetic paste creates one element (so the synthetic event is effective),
and the same drop reaches Lobby's upload handler once and adds no element (Excalidraw's own drop path
never runs).

## Engine behaviour (verified in the dist)

- **`onPointerUpdate` is silent for read-only roles with the selection tool, as the plan says.**
  `handleCanvasPointerMove` calls `savePointer` only if the active tool is supported (index.js
  45141-45145), and `savePointer` returns early for the same reason (47784-47786); `isToolSupported`
  allows only `laser` and `custom` under `interaction` (42465-42479). Measured 0 calls with no tool, 11
  with Lobby's comment tool active. Lobby's own listener measured ~15 Hz on a 30-step move.
- **Finding: Excalidraw refuses the SELECTION tool too.** Under `interaction`, `App.setActiveTool` checks
  `isToolSupported(tool.type)` first (44343-44350) and refuses every non-laser, non-custom tool, the
  selection tool included, with the console warning `"selection" tool cannot be activated while the
  editor is non-interactive (see "interaction.enabled.tools")` (observed). A viewer who picked the comment
  tool would stay in it, and a primary-button drag pans only when no capturing tool is active
  (`pan.start`, 28810-28815; `isActiveToolPointerCapturing`, 48043-48048). Lobby's `setTool('select')`
  for read-only roles therefore installs the neutral selection state through
  `updateScene({ appState: { activeTool } })`; every other engine tool stays refused (`setTool('hand')`
  returns false).
- Pan: a non-interactive pointer-down on the canvas goes to `pan.start` when navigation is on
  (45577-45590); view mode is forced on for a non-interactive editor (47881; 43126-43138), so a
  primary-button drag pans with no capturing tool. Middle and right drags pan too (probed separately:
  scroll moved 150/90 px per drag with left, middle and right).
- Zoom keys: the non-interactive keydown listener is `handleNavigationModeKeyDown` on the container
  (49253-49258; 43029-43035), which runs only actions marked `navigation` (zoom in/out/reset/fit).
- Copy, cut, paste and drop: for a non-interactive editor `addEventListeners` returns (49327) before the
  document `copy` (49346), `paste` (49390) and `cut` (49396) listeners and the container's `drop` guard
  (49416) are added, and the container's React `onDrop` is `undefined` (48682). So Excalidraw can neither
  copy nor paste for these roles, whatever Lobby's policy says; Lobby's capture listeners add the policy
  (guests: `preventDefault` on copy) and stop the browser's default drop.
- The container gets the classes `excalidraw--view-mode excalidraw--non-interactive
  excalidraw--navigation` (48663-48666; observed).

## Deviations from the plan

- The plan lists PgUp/PgDn as Lobby-owned; the spike has no handler for them, so they are blocked for
  read-only roles (Excalidraw's own navigation handler would page-scroll, 43041-43059). Wave 2 must give
  Lobby's handler the page scroll, or delegate them for read-only roles.
- **Plan correction (§2.3.4, §2.7):** add that `CanvasPort.setTool('select')` must not go through
  `api.setActiveTool` for read-only roles (Excalidraw refuses it); it sets `appState.activeTool` to the
  selection tool. Without it, read-only users cannot leave the comment or vote tool.
