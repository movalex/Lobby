### How the plugin works

- **Scope: the engine's whole dependency tree**, not only `@excalidraw/*`: `@excalidraw/excalidraw` and
  every package it depends on, transitively (dependencies and optionalDependencies, not peers), read from
  the installed `package.json` files: **266 packages** (mermaid, katex, codemirror, radix, lodash, d3…).
  React and tldraw are not in it; Lobby's own code is never touched.
- **Only literals are touched**, found with Vite's parser (`parseSync` from `vite`): string, template and
  regex literals, never module specifiers, never code, never comments (license notices stay verbatim). In
  them: the host of every absolute URL (`https://host`, `//host`, `\/\/host` in a regex source) becomes
  `blocked.invalid` (RFC 6761), except the XML-namespace host `www.w3.org` (an identifier, never
  requested) and local hosts; the listed hosts are also rewritten as bare text (`"player.vimeo.com"`,
  `youtube\.com` in the embed regexes).
- **The font fallback becomes same-origin.** `ExcalidrawFontFace.ASSETS_FALLBACK_URL`
  (`https://esm.sh/@excalidraw/excalidraw@0.18.0/dist/prod/`, `chunk-FN755BR4.js:1277`) is replaced by
  `${location.origin}/excalidraw-assets/`. Rewriting only its host was not enough (see the CSP findings).
- **Verification in the build:** after the rewrite every module's literals are scanned again; a foreign
  host left fails the build (`this.error`), so an engine bump that adds one breaks the build until it is
  listed. `LOBBY_HOST_REWRITE=off` builds the "before"; `LOBBY_HOST_REWRITE_REPORT=<file>` writes counts.
- Built output (`LOBBY_HOST_REWRITE_REPORT`, a build at 73a6c64): 2,402 engine-tree modules transformed;
  29 distinct URL hosts rewritten (82 occurrences), 18 listed hosts rewritten as bare text (37), the font
  fallback (1); 0 modules the parser could not read; 0 hosts left.

### What the policy needs, and why

1. **`index.html`'s inline theme script** (the no-flash dark-mode boot) is blocked by `script-src 'self'`
   (1 violation on every page load). Needs its sha256 in `script-src` (or moving it to a file). Not in the plan.
2. **zod's eval probe.** zod 4.6.5 tests `new Function("")` once (`allowsEval`,
   `node_modules/zod/v4/core/util.js:218-230`) to pick its JIT; the throw is caught but Chrome reports a
   `script-src` violation on every page (sign-in and board). zod's own comment says to use `jitless` under a
   strict CSP. Fix (app code, not this owner's): `z.config({ jitless: true })` before any schema runs (the
   app's bootstrap). Not engine-related; it exists today.
3. **Excalidraw's font fallback URL.** Chrome checks CSP for **every source of a FontFace when the
   FontFace is constructed**, not when it loads (measured with a one-FontFace page: 1 violation right after
   `new FontFace(..., 'url(/a.woff2), url(https://blocked.invalid/b.woff2)')`, before any load, and a
   request event). The engine constructs all ~230 faces at its first render, each with the fallback as the
   last source, so with the host merely rewritten the board page logged **230 `font-src` violations** and
   230 blocked requests at load, although every local font loaded. With the fallback patched to the
   page's own asset base: 0. So §2.12's layer 2 must rewrite the fallback to a same-origin URL, not only
   strip the host.
4. **Excalidraw's SVG font inlining needs `unsafe-eval`.** Subsetting uses the engine's WebAssembly
   (`chunk-Z5NKEFVG`, woff2 + harfbuzz) through Emscripten embind glue that builds functions with
   `new Function` (`Function("dynCall", ...)`, `dn(Function, m)` in that chunk). Under the policy: 1
   `script-src eval` violation, 3 uncaught `EvalError` page errors (the subset worker throws, stops
   answering, "Active worker did not respond for 1000ms", falls back to the main thread, which throws
   again), 10 "Skipped glyph subsetting" warnings; the export still embeds the 10 fonts as `data:` sources
   but whole (a 506 KB SVG). Lobby's SVG export (§4.5) should call `exportToSvg` with
   `skipInliningFonts: true` and embed its own `@font-face` rules (whole woff2 files as `data:` URLs), which
   logs nothing (measured: 0 violations with `skipInliningFonts`). `'wasm-unsafe-eval'` does not help: the
   eval is JavaScript.
5. `img-src data:` (Excalidraw's placeholder and cursor SVGs) and `blob:` (Lobby's loader) are needed as
   the plan says; `style-src 'unsafe-inline'` is needed (the text editor and canvas elements are styled
   inline); `worker-src 'self'` covers the subset worker (a same-origin module chunk) and `blob:` stays for
   Clerk. `font-src 'self'` suffices once the fallback is same-origin. `connect-src 'self'` covers the
   same-origin WebSocket in this local setup; staging needs the sync origin (below).
6. Informational: today's **tldraw** board also fetches a `data:application/json` URL (2 `connect-src`
   violations per load, `dist-esm-*.js`, tldraw's) and shows the same zod and inline-script violations.

## Deviations from the plan, and why

- The plugin covers the engine's dependency tree and rewrites every URL host in it, instead of a
  `renderChunk` replace of a fixed origin list "in Excalidraw's chunks": the list was incomplete (above),
  and chunk-level replacement cannot tell engine code from app code in shared chunks.
- The plugin also rewrites one piece of engine code (the font fallback base) because a host rewrite alone
  still breaks a strict CSP (finding 3).
- The CSP run uses the dev provider, so it cannot exercise Clerk; the header therefore has no Clerk origins.
- The pass criterion (0 violations) is met only with the zod fix, which is app code outside this owner's
  files; it is emulated in the run and proposed below.
