## How it works (for the adapter owner)

- `record(scene)` at a step boundary diffs against `lastLocal` (fast path on `version`/`versionNonce`), makes
  one entry per step and clears redo. `absorb(before, after)` takes remote changes and repairs into
  `lastLocal` field by field (never a step). `markPushed(seq, ids)` ties unsent parts to a push;
  `onAck({seq, r})` drops rejected parts and denied groups and folds `fix` (fields, or `c:<key>`) into the
  side that push carried, into later entries recorded against the old value, and into `lastLocal` when the
  scene holds the fixed value. `foldLocalFix` does the same for the client's own re-keys.
- `undo(scene, ctx)` / `redo` return `{patches, elements, applied, skips, kept}`; the adapter installs
  `patches` with `updateScene(…, NEVER)` and pushes them. `kept` counts elements with a non-silent skip (the
  "N changes kept" toast). `ctx.isLeasedByOther(leaseId)` and `ctx.recompute(ids, next)` are injected.

## Deviations from the plan, and clarifications

1. **The compare-and-set unit.** Changes are recorded per field. They are compared and restored **per group for
   coupled geometry** (`pos`, `shape`, `layout`: the fields of that group this entry recorded go back together
   or not at all) and **per field elsewhere** (style, meta, textStyle, bind, z, file are independent fields).
   The plan says "per field group" in §2.8 and "per field" in its revision table; neither alone is right:
   per field left U7's child 2 at C's `x` with my old `y` (a position nobody chose); per whole group would
   block my resize because someone rotated. Only recorded fields are compared, so an unrelated field of the
   same group (Bob's `angle`) never blocks.
2. **A no-op is not a skip.** When the current value already equals the target (e.g. a repair already nulled a
   binding I am undoing), nothing is written and nothing is "kept". Without this rule U10's repair case would
   show a false toast.
3. **`boundElements` skips are silent.** They are bookkeeping; the server keeps them symmetric (§2.4.4).
4. **Redo re-applies only what the undo applied.** That is what makes "never resurrected, including by redo"
   hold (U6): a skipped delete leaves nothing to redo.
5. **U10's "stack length equals A's real actions" should read "≤".** An entry whose only change a `fix`
   cancels (a pure bind to an element the server found deleted) becomes empty and is dropped, so Ctrl+Z does
   not spend a keypress on a no-op. A fix never adds a step. (In the U10 test the bind also moved the arrow's
   end point, as Excalidraw does, so the entry survives and the count is 4 for 4.)
6. **Known edge, not covered:** if I delete X by undo, someone restores X and then deletes it again, my redo of
   that entry would revive X. It needs a version check on the life field; noted for wave 2.
7. `fields.ts` duplicates the §3.2 group map because `packages/canvas-schema/src/groups.ts` does not exist yet;
   it must import that map when it lands (one map, one coverage test).
8. Purged ids are reported as `orphan` (the plan's table uses the same reason for "purged or missing parent").
