# A13: bundle size of the Excalidraw board route, against today's tldraw board route

**Status: PASS** (reported, 3 of 3 runs back to back, identical numbers, 2026-09-28, branch
`spike/a-render` at 73a6c64). An earlier series at 9bb6340 (before the loader batched `addFiles`) gave the
same numbers to within 0.3 KiB on the render-lab route and 0.2 KiB on the lazy total. Plan §8.2 A13:
"reported against ≈881 KiB gzip today". There is no gate; the numbers below are the result.

## Method (the same for both routes)

`node e2e/spike/csp/dist-report.ts --run N` builds apps/web with `--manifest` and measures, from the
built files, the **static-import closure** of a route: every JS and CSS file the browser must load before
the route's page renders (entry `index.html` → its imports → the route's lazy page chunk → its imports).
Sizes: zlib gzip at the default level (6), plus gzip -9, brotli -11 and raw.

| Route | Build | Closure |
|---|---|---|
| tldraw board (today) | production build, no `VITE_LOBBY_ENGINE`, no dev auth (what staging ships) | `index.html` + `src/board/BoardPage.tsx` |
| Excalidraw engine route | `VITE_LOBBY_ENGINE=excalidraw` + dev auth (the spike build), host-rewrite plugin on | `index.html` + `src/canvas/spike/SpikeRoute.tsx` + `pages/engine.tsx` (ExcalidrawHost only) |
| render-lab route | same | `pages/render-lab.tsx` (+ Lobby's loader, overrides, guard) |
| app shell | production build | `index.html` alone |

Cross-check at run time: `e2e/spike/tests/render-a13-runtime.spec.ts` opens `/spike/engine` and sums the
gzip size of every same-origin JS/CSS response (files read from the build on disk).

A per-package split comes from source maps (a `--sourcemap` build of each; every generated span is
attributed to its source; a chunk's gzip size is split by raw share, the source-map-explorer method,
`e2e/spike/csp/attribution.ts`).

## Findings

1. **Today's app shell already carries tldraw**: 471.7 KiB gzip of the 640 KiB entry JS is tldraw and its
   rich-text stack, so the sign-in page and the dashboard download most of tldraw too, although the board
   page is lazy (`App.tsx`'s comment says the dashboard and sign-in "should not have to download it").
   Some module the entry imports statically pulls it in. This is a current-build issue, not Excalidraw's;
   the cut-over removes it.
2. **The spike's Excalidraw route therefore includes tldraw** (via the shell): 1305.9 KiB is not the size
   of a future Excalidraw board route.
3. **Projection of the post-cut-over board route** (estimate, from the attribution): the engine route
   (1305.9) minus the tldraw family in the shell (471.7) = **834 KiB**; plus the Lobby board code the tldraw
   BoardPage chunk carries today (231.2, features and board UI, which moves to the Excalidraw page) =
   **≈1065 KiB**; plus pdf-lib (~132 KiB, Lobby's PDF export, in today's BoardPage chunk) if it stays eager
   = **≈1197 KiB**, against 1086 KiB today.
4. **~120 KiB of mermaid, d3 and marked load eagerly** with the engine route although Lobby never uses
   Excalidraw's mermaid or text-to-diagram features: `@excalidraw/mermaid-to-excalidraw` is a dynamic
   import, but rolldown hoists parts of its graph into chunks the engine imports statically (the
   `harness-*` chunk carries 26 KiB of mermaid; `chunk-DU6HZSFF`, `chunk-4HAMMTFA` and others the rest).
   Removing it (stub the module in the Vite config, or chunk rules) would bring the projection to
   ≈945-1077 KiB. Not done here: it changes the build config beyond this owner's one-line wiring.
5. **The plan's "≈881 KiB gzip" for today's board route does not reproduce**: the same route measures
   1045.7 KiB gzip JS (1086.2 with CSS) at this commit; 908.7 KiB brotli (JS + CSS). The plan's number was
   taken on an earlier build or with a different compressor; the table above measures both routes the same
   way, which is what the comparison needs.

## Deviations from the plan, and why

- The Excalidraw route measured is the spike's `/spike/engine` (ExcalidrawHost only), the only Excalidraw
  route that exists; the Lobby board page on Excalidraw is wave 2-3 work. The projection above is labelled
  as an estimate.
- The static closure is used as the primary number (deterministic); the run-time sum confirms it.
