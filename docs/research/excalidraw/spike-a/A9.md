## Engine behaviour (file:line, installed 0.18.0-1118751)

- **E5 holds.** `Fonts.onLoaded` (`@excalidraw/excalidraw/dist/dev/chunk-FN755BR4.js:3026-3054`) only
  deletes shape caches and `charWidth` caches of text elements and their containers and calls
  `scene.triggerUpdate()`; no `mutateElement`, no version change. Measured: 0 ops, 0 drift, 0 size changes.
- **Consequence to keep in mind:** a label measured before its font loaded keeps that width/height after
  the font loads (nothing re-measures on font load; only `actionChangeFontFamily` re-lays out,
  `index.js:8470-8483`). The server must lay out text with the real metrics (plan §2.11 metrics table);
  otherwise the stored layout and the drawn glyphs disagree until someone edits the text. A10 saw the same
  from the other side: opening and closing the label editor without typing rewrote a label's `x`/`width`
  (measured by `convertToExcalidrawElements` before Nunito loaded) and pushed that as an edit.
- **All ~230 font faces are registered and added to `document.fonts` at the first render**, whatever the
  scene (`Fonts.registered` → `init()` `:3072-3082`, `:3207-3226`; `loadFontFaces` adds every non-local face
  `:3108-3118`); only the faces a drawn text needs are fetched (27 files here). Under CSP this matters: see
  A12 (every face's source list is CSP-checked at construction).
- **`fontFamily: 10` (Assistant) has no registered faces**: exporting it logs `Couldn't find registered
  fonts for font-family "10"` (`:3155`). Plan §3.5's validator should refuse 10 as well as 9.
- **Liberation Sans (9) is not self-hosted** (plan §2.12): the local file 404s and, with the plugin's font
  fallback patch (A12), the fallback source is the same-origin asset base, so it 404s twice and nothing
  leaves the machine (0 foreign requests). Before the patch this went to esm.sh (SCAFFOLD finding 1) and,
  with the host only rewritten, to `blocked.invalid`.
- **Font subsetting in a Worker depends on the bundle's chunk split.** Excalidraw subsets fonts for SVG
  export in a module worker (`subset-worker.chunk.js`, created from the chunk's own `import.meta.url`,
  fallback to the main thread at `chunk-FN755BR4.js:1095-1106`, which also sets `shouldUseWorkers = false` for the rest of the session). In the builds before the font-fallback
  patch, rolldown made the worker chunk side-effect-import the chunk that also holds Lobby's app entry; the
  worker died with `ReferenceError: document is not defined` (measured by importing the chunk in a probe
  worker) and every export subset on the main thread ("Failed to use workers for subsetting, falling back
  to the main thread"). After the patch the split changed (the worker imports only two engine chunks) and
  the worker starts. Nothing in the source decides this; wave 3b should pin the engine's chunks
  (`build.rolldownOptions.output.advancedChunks` / `manualChunks`) and keep the probe.

## Deviations from the plan, and why

- "Every font the package ships" includes Liberation Sans, which Lobby does not serve, and Assistant,
  which the engine does not register for canvas text; both are in the scene on purpose. They do not change
  the result (0 ops) but they produce console errors, which this check records instead of asserting none.
- Only the `updateScene` path (Lobby's: the scene arrives from sync after an empty `initialData`) is
  measured; `initialData` with elements (the engine's own `loadSceneFonts` at init, `index.js:43354-43356`)
  is not Lobby's path.
