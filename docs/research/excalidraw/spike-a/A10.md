# A10: render overrides, collapse opacity and Lobby's hit-test guard

**Status: PASS** (3 of 3 runs back to back, 2026-09-28, branch `spike/a-render` at 73a6c64; an earlier
series at 9bb6340 also passed 3 of 3). Plan §8.2 A10 ("drag offsets move a note and its label
together; opacity 0 hides a branch; the hit-test guard stops clicks on hidden elements"; pass: pixel
probes), with §2.7 and §4.7.

## What was built

`apps/web/src/canvas/overrides.ts` (+ `overrides.test.ts`, 9 unit tests):

- `RenderOverrides`: the single owner of `api.setElementRenderOverrides`. Writers call `setDrag(peer,
  offsets)`, `clearDragFor(ids)` (a commit arrived), `setHidden(source, ids)` (a collapse). It merges them
  into one snapshot (most recently updated drag source wins; hidden → `opacity: 0`), expands a hidden set
  to bound labels and, for frames, to frame children and their labels (the engine does neither), coalesces
  changes into one submit per microtask and skips a snapshot equal to the last one (the engine repaints
  on every submitted snapshot, `types.d.ts:1095-1110`).
- `installHitGuard({ wrapper, api, overrides, onBlocked })`: capture-phase listeners on Lobby's board
  wrapper. They find the element Excalidraw would pick at the pointer by the same rules as
  `App.getElementsAtPosition` / `getElementAtPosition` (`@excalidraw/excalidraw/dist/dev/index.js:49977-50037`,
  threshold `getElementHitThreshold` `:50038-50046`), with `hitElementItself`, `hitElementBoundText`,
  `getContainingFrame` and `isCursorInFrame` from `@excalidraw/element`. When that element is hidden, or is
  under a peer's drag preview, they swallow `pointerdown` (primary button; not while Space is held, not with
  the hand or laser tool), `dblclick`, `contextmenu` and a one-finger `touchstart`, and report it
  (`{ id, reason: hidden | moving(peer) }`, for the "Bob is moving this" toast). A selection post-filter
  removes hidden ids after Excalidraw's own box or lasso selection.

Page: `/spike/render-lab` (the guard can be switched off from the spec to show the engine's own
behaviour). Spec: `e2e/spike/tests/render-a10-overrides.spec.ts` (4 tests). Scene: notes D, M, V in row 1;
a "branch" in row 2: notes B1, B2, an arrow A, a free text T, a frame F with a note C inside; a visible note
V2. All notes are `stickynote` with a bound Nunito label, `created: null`.

## Findings (file:line, installed 0.18.0-1118751)

- **Offsets: a note and its label move together; the document does not.** `setElementRenderOverrides`
  (`index.js:43855-43870`) copies the snapshot, stores its offsets and calls `forceUpdate()`; no document
  change, no history, no `onChange` (the probe's `onChange` count did not move). Measured: the old spot is
  background, the new spot is note fill, the label's ink (322 px) moved with it.
- **An offset set on a bound label alone is ignored** (the label stayed, 322 px at the old place, 0 at the
  shifted one), as the types say. Lobby never sets label offsets.
- **Opacity on a container does not hide its label** (engine only: B1's fill vanished, its label stayed,
  311 dark px). Hiding a branch therefore needs explicit label ids, and frame children need explicit ids
  too; `expandHidden` does both (9 ids from 5 requested).
- **Hit tests, selection and editing stay at document values** (`types.d.ts:1095-1110`): with the guard off,
  a click on the hidden B1 selected it and a double-click opened its label editor. With the guard on:
  click, double-click, drag, right-click and a box selection over the whole branch left the branch
  untouched (box selection selected only V2), a visible note was still selectable, and the guard logged
  `pointerdown`, `dblclick` and `contextmenu` on B1.
- **Remote-drag deviation (§2.7) confirmed:** with a peer's offset on M, a press on M's document spot is
  swallowed (`moving`, source `peer-bob`); a press on its drawn spot hits nothing (the note is not there in
  the document); after `clearDragFor` the document spot selects M again.
- **Not guarded: hover.** Over a hidden element the canvas cursor is still `move` (Excalidraw sets it in
  `handleCanvasPointerMove`, `index.js:45504-45525`, from the same document hit test). The guard does not
  touch `pointermove` (presence reads it, §2.7). A cosmetic gap; a wave 3d option is to reset the cursor
  after Excalidraw's handler.
- **The guard makes a dead zone:** a left-press on a hidden element's area starts nothing (no box select, no
  pan by drag); Space+drag and the hand tool still pan. Expected with "cannot be clicked" (B12), stated here.
- Engine gap found while building the scene: `convertToExcalidrawElements` cannot bind an arrow to a
  `stickynote` (`bindLinearElementToElement`, `@excalidraw/element/dist/dev/index.js:24302-24380`, handles
  text, rectangle, ellipse and diamond; any other type hits `assertNever` and the next line throws
  "Cannot read properties of undefined (reading 'id')"). Relevant to the converter (tldraw arrows bound to
  notes) and server-made connectors: they must set `startBinding`/`endBinding` and `boundElements`
  themselves. The spec uses an unbound arrow.
- Side observation (label layout): with the guard off, opening and closing a label's editor without
  typing changed the label's `x` and `width` (one op, fields `["x","width"]`): the label had been measured
  by `convertToExcalidrawElements` before Nunito loaded, and the editor re-measures with the loaded font on
  close. See A9.

## Deviations from the plan, and why

- The touch path (a hidden element under a one-finger `touchstart`, Excalidraw's own double-tap detector)
  is implemented in the guard but not exercised here: the spike config is desktop Chromium without touch.
  Spike B12 runs touch emulation.
- Selection post-filtering is done on `onChange`; Ctrl+A (Lobby-owned, §2.3.3) belongs to the input owner.
