# A5: `ui={false}` hides Excalidraw's UI; Lobby's toolbar drives the tools

**Status: PASS** (3 of 3 runs; see Runs). Branch `spike/a-host`, Windows 11, Node 24, Playwright 1.63.0
headless Chromium shell, engine 0.18.0-1118751.

Plan §8.2 A5: *`ui={false}` hides Excalidraw's UI; Lobby's toolbar drives tools. Pass: visual pin test.*

## Which pin, and why

Two pins, neither a committed screenshot baseline:

1. **DOM assertion (primary).** Inside `.excalidraw`, no element that is visible (non-zero box, not
   `display: none` / `visibility: hidden` / opacity 0) may paint or accept anything: no own text, no
   background, border or shadow, no `button`/`input`/`select`/`textarea`/`a[href]`/`[role=button]`/
   `[role=menu]`, no `img`, no `svg` that draws a shape. Canvases (`canvas.excalidraw__canvas`) and
   Excalidraw's text-editing textarea (Lobby's editing surface) are the only exceptions. On top, 33
   named selectors of Excalidraw's UI must have 0 visible matches (`.App-toolbar`, `.App-menu`,
   `.main-menu-trigger`, `.dropdown-menu`, `.layer-ui__library`, `.library-menu`, `.sidebar-trigger`,
   `.zoom-actions`, `.undo-redo-buttons`, `.help-icon`, `.welcome-screen-*`, `.HintViewer`, `.Island`,
   `.ToolIcon`, the footer halves, `.context-menu`, `.popover`, `.selected-shape-actions`,
   `.compact-shape-actions-island`, `.mobile-toolbar`, `.hyperlink`, …). Checked in six states: empty
   scene; a note selected (the default UI would show shape actions); the text editor open (text
   properties); a line in its linear editor; after a right-click (Excalidraw's context menu); and the
   phone form factor (390 x 844, Excalidraw's mobile toolbar).
2. **Pixel check without a baseline.** With an empty scene, the viewport screenshot (decoded in the spec
   with a 60-line PNG decoder over `node:zlib`) must have every pixel outside Lobby's toolbar box equal to
   the canvas background `appState.viewBackgroundColor` (#ffffff, tolerance 2 per channel). Any painted
   Excalidraw control, in the DOM or on a canvas, would fail it.

Why not a baseline screenshot: it is brittle across GPU, font hinting and OS (these specs also run on a
laptop and in CI), it needs binary files in the repo and a re-approval at every Excalidraw bump, and when
it fails it does not say what appeared. The DOM pin names the element; the pixel pin needs no baseline.

drag makes one rectangle (Excalidraw's own tool, chosen by Lobby); Note + a click places a `created: null`
note and opens its editor at once (the "New element" row of §2.9.2), typed text lands; Text + a click on
empty canvas places a free text and opens it; Comment + a click reaches Lobby's handler and creates
nothing.

## Engine behaviour

- `ui={false}` is honoured in every state tried, including the phone form factor and after a
  right-click. What remains in the DOM is structural and invisible: the empty `.layer-ui__wrapper` and
  footer containers (scaffold finding, index.js 30857) and one full-size, empty `div.SVGLayer > svg` (39927-39941, the
  layer Excalidraw draws laser and eraser trails into). The DOM pin reports that `svg` separately as
  "visible but draws nothing".
- The container carries `excalidraw--ui-hidden` (`!isDefaultUIEnabled()`, index.js 48670).

## Deviations from the plan

- The plan's fallback "hide by CSS, pinned by a visual test" was not needed: `ui={false}` works in
  0.18.0-1118751. The pins above guard against a future bump that renders something again (the prop is
  marked WIP in `types.d.ts`).
