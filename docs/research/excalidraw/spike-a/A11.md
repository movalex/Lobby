## What was built

- `apps/web/src/canvas/preview/CheckpointPreview.ts`: a checkpoint drawn on a plain `<canvas>` with the
  engine's exporter, never a second `<Excalidraw>`. Lobby's camera is `{ x, y, zoom }` (the scene point at
  the view's top-left). An **overview** bitmap of the whole checkpoint is rendered once at the largest
  scale that fits 16.7 Mpx; drag pans, Ctrl/Cmd+wheel zooms around the pointer, a plain wheel pans, and
  each frame is a `drawImage` of the bitmap. When the camera zooms past the overview's resolution, a
  **detail** pass renders only the elements in view at the view's scale, 150 ms after the camera stops.
  Checkpoint images come from Lobby's loader into a preview-only files map (never `api.addFiles`).
- Pages `/spike/render-preview` (live board left, preview panel right) and `/spike/render-two` (two
  `ExcalidrawHost` instances side by side, B dark).
- Specs `e2e/spike/tests/render-a11-preview.spec.ts` (a small checkpoint; the heavy board) and
  `render-a11-two-instances.spec.ts`.

## How exportToCanvas frames its output (why the preview works as it does)

`exportToCanvas` ignores the appState's scroll and zoom: it draws with `scrollX = -minX + exportPadding`,
`scrollY = -minY + exportPadding` and the default zoom over the bounds of the **root** elements plus the
frame name labels it adds above frames (`@excalidraw/excalidraw/dist/dev/chunk-FN755BR4.js:4592-4668`,
`getCanvasSize` `:4845-4850`, `addFrameLabelsAsTextElements` `:4540-4560`, `getRootElements`
`@excalidraw/element/dist/dev/index.js:12978-12983`); the public wrapper restores the elements first
(`restoreElements(..., { deleteInvisibleElements: true })`, `index.js:15391-15436`). Lobby therefore never
passes a camera: it controls the output with `getDimensions` (size and scale) and fixes the bitmap's origin
with an invisible anchor rectangle that encloses everything (so its top-left is known exactly), then maps
bitmaps to the view itself. In the detail pass, frames are clipped to the view (a local copy) so a 4,000-
unit frame does not make the bitmap cover the whole frame. At 9,220 elements the overview took 269-273 ms
and a detail pass 3 ms (25 elements in view at zoom 1).

Limits of this first version (for wave 3e): until the detail pass lands (150 ms after the camera stops)
the overview is scaled; right after a pan the clipped frame edges of the previous detail bitmap can show
at the old view's border for up to 150 ms; a checkpoint larger than about 16,000 × 16,000 units gets an
overview coarser than 1 px per 4 scene units (the heavy board: 0.228 px per unit), so zoomed-in views rely on the detail pass.

**Shared render throttle, explained:** with `EXCALIDRAW_THROTTLE_RENDER = true` (Lobby sets it, plan
§2.3.2) the static canvas is repainted through `renderStaticSceneThrottled`, **one** `throttleRAF` for the
whole module (`chunk-FN755BR4.js:3786-3790`). `throttleRAF` keeps only the last caller's arguments
(`@excalidraw/common/dist/dev/index.js:2662-2680`), so when two instances ask for a repaint in the same
frame, the first one's repaint is dropped until something else repaints it; and an instance's `destroy()`
cancels the shared throttle (`index.js:24386`), dropping the other's pending repaint. The probe (both
instances recolour a note in one task, the canvases are read 3 frames later, 20 trials) measured the
missed repaints above; with the throttle off, none. This also explains a flaky assertion in an earlier run
of this spec (run 3 of the first series, instance A's note not yet painted 300 ms after its update); the
spec now records pixels instead of asserting them.

**Conclusion for §4.6:** the plan's choice holds: the checkpoint preview uses `exportToCanvas` and Lobby's
own camera, not a second `<Excalidraw>`. Two instances do mostly work, but share editor atoms and the
render throttle, so a second instance would need `EXCALIDRAW_THROTTLE_RENDER` off and no Tab/shape-switch,
eye dropper, search focus or other atom-driven UI, which is not worth it.

## Deviations from the plan, and why

- The preview's pan/zoom are pointer and wheel only (no keyboard); the history UI is out of scope (§8.1).
- The small checkpoint uses images from the fixture server; the heavy one carries 200 images loaded by
  Lobby's loader into the preview-only map (all 200 loaded).
