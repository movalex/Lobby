# A3 — server-made notes lay out like the browser's (spike A, node owner)

**Status: PASS (3/3 runs).** Line breaks differ in **0 of 208** labels in every run (criterion: ≤ 3). With the
plan's literal design — a per-character width table without kerning — the same corpus differs in **6 of 208**,
which would **fail**. The table therefore carries pair kerning (plan correction below).

Engine: `@excalidraw/excalidraw`, `element`, `common`, `math`, `fractional-indexing` **0.18.0-1118751**.
Branch `spike/a-node`; runs made on the working tree committed as the "A3/A8/A15/A16 evidence" commit (parent 2c5c860).

## How the table was measured (`packages/canvas-schema/src/engine/text-metrics-table.json`, 95 KB)

`node apps/web/test/engine-probe/a3/calibrate-table.ts` (same page, same fonts, same provider, at 100 px):

| Family | Advances | Kerning pairs (non-zero, of 165×165) | Han / kana / full-width | Hangul | Emoji | Flag (fallback) |
|---|---|---|---|---|---|---|
| 5 Excalifont | 270 | 1,474 | 1 em | 0.921 em (0.893–0.949) | 1.37305 em | 0.949 em |
| 6 Nunito | 270 | 5,385 | 1 em | 1 em | 1.37305 em | 0.949 em |
| 8 Comic Shanns | 270 | 0 (monospace) | 1 em | 1 em | 1.37305 em | 0.949 em |

- Advances: ASCII, Latin-1, typographic punctuation, common symbols, and the 26 regional-indicator letters.
  Chromium on Windows draws a flag as **two letters** (Segoe UI Emoji has no flag glyphs), 0.73–1.16 em per flag
  depending on the letters, so flags use per-letter advances, not one class width.
- Class samples are **held out**: any sample character that the corpus uses is dropped before measuring
  (43 Han, 45 kana, 10 Hangul, 8 full-width, 4 flags dropped), so CJK and emoji are tested on unseen glyphs.
- Linearity: `measureText` at 16/20/24/28/36 px equals the 100 px table × size within **1.4e-6** relative
  error, so one table at 100 px is enough (no hinting-rounded advances in canvas `measureText`).
- The provider (`createTableTextMetrics`): graphemes via `Intl.Segmenter`, `adv` + `kern[prev+cur]`,
  else a class width (Han, kana, Hangul, full-width, emoji, flag, other), combining marks 0. It parses the
  first family of Excalidraw's font string (`getFontString`, common `index.js:2618-2633`), counts unknown
  families and measures them as Nunito.

## Engine behaviour recorded

- Without a provider, `newTextElement` in Node throws `ReferenceError: document is not defined`
  (`CanvasTextMetricsProvider` constructor, element `index.js:5731-5735`, created lazily by `getLineWidth`,
  `5754-5758`). The sync process must call `installServerTextMetrics()` at start-up.
- `wrapText` measures whole test lines with `getLineWidth(testLine)` for multi-character tokens and sums
  cached per-character widths only for single-code-unit tokens (`isSingleCharacter`, element `index.js:6113`,
  `6255-6257`). Whole-line measurement is why kerning matters.
- `charWidth` caches by `char.charCodeAt(0)` per font string (element `index.js:5772-5796`): two astral
  characters with the same high surrogate share one cached width inside `wrapWord`. Same in both runtimes, so
  no divergence, but it is an Excalidraw quirk.
- `newTextElement` stamps `created` with the wall clock unless given (`_newElementBase`, element
  `index.js:16371`). The first version of Lobby's builder only nulled the note's `created`, and its
  determinism test failed 1 run in 3 when two builds straddled a millisecond. Fixed: server-made labels get
  `created: null` too (server-owned field, §3.2), and the test now always crosses a millisecond boundary.

## Deviations from the plan, and corrections

1. **Plan §2.11 says the metrics are "a per-character width table".** Measured: that alone gives 6/208,
   over the 3/208 criterion. **Correction:** per-character advances **plus measured pair kerning**, per-class
   widths for Han/kana/Hangul/full-width/emoji, and per-letter advances for flags. The criterion itself is
   right and is met with margin (0/208).
2. The plan's 3/208 figure came from the 8 converted templates. This check used a synthetic, harder corpus (as
   the task asked); the templates are re-checked by the converter owner in B8.
3. **Scope of "matches the browser".** The table reproduces Windows Chromium with the package's fonts. CJK and
   emoji go through OS fallback fonts (Xiaolai only for Excalifont; Segoe UI Emoji / system CJK otherwise),
   so on macOS or iOS (Apple Color Emoji, PingFang) the browser's own layout can differ from the server's.
   That is covered by design: the lease holder re-fits on the next edit (§2.9.4), and nobody else re-lays out.
   Risk to record: Korean under Excalifont uses a median Hangul width (±3%); long Korean Excalifont labels
   could wrap differently. A per-syllable Hangul table would fix it (≈11k entries) if B8 finds real cases.
4. The table must be re-measured on any Excalidraw bump or font change (`calibrate-table.ts`), then A3 re-run.
