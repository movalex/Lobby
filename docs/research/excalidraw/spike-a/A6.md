## Second correction (fix round 2, 2026-09-29): outside the text editor, chords were delegated by physical key

The corrected report still said "0 downloads, dialogs or pickers". **That was false outside the text
editor, on some keyboard layouts.** A second independent verifier sent key events through CDP the way
Chromium on Windows reports a non-QWERTY layout (`key` = the layout's character, `code` = the physical
key) and found:

- Lobby delegated Ctrl+D, Ctrl+G, Ctrl+Shift+L, Ctrl+= / - and Ctrl+[ ] to Excalidraw by physical `code`
  (`letterIs` was code OR key; the zoom and z-order rules were code only), while most of Excalidraw's
  handlers test `key`. **Bone Ctrl+Shift+S** (code `KeyL`, key `S`) passed as the lock chord and
  Excalidraw ran `saveFileToDisk`: `showSaveFilePicker`, a whole-board save that bypasses the export
  policy (3/3 on Windows, 3/3 under macOS emulation). Colemak Ctrl+S (code `KeyD`) and Neo 2 Ctrl+O (code
  `KeyG`) were also passed through; `canvasActions` happened to stop them.
- **German Ctrl+Shift+ß** (code `Minus`, key `?`, passed as zoom) and **Dvorak Ctrl+Shift+[** (code
  `BracketLeft`, key `?`, passed as z-order) opened the help dialog: Excalidraw's `onKeyDown` opens it on
  key `?` whatever the modifiers (index.js 44013), before any action.

**The rule now (`keymap.ts`: `delegatedChord`, `engineChordAction`).** A Ctrl/Cmd chord outside the
text editor is delegated only when Excalidraw itself would run exactly one delegated action for that very
event, decided the way its handlers decide:

- the key its handlers compare is `key` after its CapsLock fix (43925-43939). `code` is read only where
  the delegated action's own keyTest reads it, so duplicate, group, ungroup and lock are decided by key
  (a dead key or `Unidentified` never delegates them: their keyTests have no code fallback), and zoom and
  z-order follow the physical key as Excalidraw's keyTests do (a dead key included: German Ctrl+´ on the
  physical `=` key zooms in);
- CTRL_OR_CMD is Excalidraw's: `metaKey` on macOS, `ctrlKey` elsewhere, and the other one must not be
  held. (On macOS, Ctrl+G is not group to Excalidraw: it opens the background popup, 44193-44205; the old
  rule delegated it.) No AltGr (`getModifierState('AltGraph')`), no IME;
- no handler that runs before the actions claims the event: help on key `?` (any modifiers, 44013),
  image export on Ctrl/Cmd+Shift+E (44018), the command-palette toast on Ctrl/Cmd+P (43983), page scroll,
  flowchart arrows;
- exactly one action's keyTest matches (`ActionManager.handleKeyDown` gives up on two, 23064-23069) and
  it is on the plan's delegated list (duplicate, group, ungroup, lock, the four z-order actions, zoom in,
  zoom out). All 46 keyTests of the bundle are transcribed with their line numbers
  (`ENGINE_KEY_TESTS`), and a unit test pins each name and line against the pinned `dist/dev/index.js`.

Lobby-owned letters (Ctrl+F search, Ctrl+Z / Y undo and redo, Ctrl+A) and the browser-chord list (the
chords a blocked key does not `preventDefault`: reload, tabs, windows, devtools) are now read from the
layout's character too (a Latin `key`, else `code`, as inside the editor), so Colemak's Ctrl+T on the
physical F key opens a tab instead of Lobby's search.

## The corrected rule (`keymap.ts`: `classifyTextEditorKey`, `isKeptTextEditorChord`)

**Kept (delegated to the textarea):**
- every key without Ctrl, Cmd or Alt: typing, dead keys and IME keys, Enter, Shift+Enter, Tab and
  Shift+Tab (Excalidraw indents), Escape, arrows, Home/End/PageUp/PageDown, Backspace, Delete. In this
  class the textarea's handler acts only on Escape and Tab, both kept;
- caret and selection moves with Shift, Ctrl or Cmd (arrows, Home, End, PageUp, PageDown); with Alt
  only on macOS (Option word moves). On Windows and Linux Alt+Left/Right/Home are the browser's Back,
  Forward and Home page, which would leave the board, so they are blocked and prevented;
- Backspace and Delete with Ctrl, Alt or Cmd (word and line deletes);
- Ctrl/Cmd+Z and Ctrl/Cmd+Shift+Z, and Ctrl+Y: the textarea's native undo and redo;
- Ctrl/Cmd+A: selects the text;
- Ctrl/Cmd+C, X, V, Shift+V and Ctrl+Insert: the clipboard arrives as copy, cut and paste events, where
  the export-policy listener applies.

A kept chord needs exactly one of Ctrl and Cmd and no Alt. Letters are read from `key` when it is a Latin
letter and from `code` otherwise, so Ctrl+Я is still Ctrl+Z. A unit test mirrors every branch above and
checks, over 77 keys x 16 modifier combinations on both platforms, that no delegated key triggers a
textarea action except Escape and Tab/Shift+Tab, and that the only delegated letter, digit or
punctuation chords are Ctrl/Cmd+A, C, X, V, Shift+V, Z, Shift+Z and Ctrl+Y.

**Typed by the browser, keydown stopped (`browser` verdict: stopPropagation, no preventDefault):** an
AltGr character (Windows reports AltGr as Ctrl+Alt; `getModifierState('AltGraph')`, now read through
`keyLikeOf`), a macOS Option character, and a key while an IME composes (keyCode 229). Excalidraw's
handler never sees these keydowns, so an AltGr+S that reports `s` on a layout without an AltGr
character cannot save.

**Blocked (stopPropagation, and preventDefault except the browser chords: reload, tabs, windows,
address bar, devtools):** every other chord with Ctrl, Cmd or Alt, whatever the other modifiers.

## Lobby's Ctrl+A

Scene: a 2-rectangle group, a locked rectangle, a rectangle marked hidden (mind-map collapse), a note
with a label. Lobby's Ctrl+A selects `g1a`, `g1b`, the note (not its label, not the locked one, not the
hidden one) and the group `grp`, with 0 element changes; Excalidraw's own select-all (control) also
takes the hidden element. Excalidraw expands selected groups to every live member, locked ones and
labels included, and drops groups with fewer than 2 members (element dist/dev/index.js 12228-12290);
`selectAll.ts` mirrors that and never adds a hidden member.

## Deviations from the plan

- The plan's row says "stopPropagation"; the spike also `preventDefault`s blocked chords (see above).
  Proposed addition to §2.3.3: *"Blocked keys with Ctrl, Cmd or Alt are also `preventDefault`ed, except
  browser chords (reload, tabs, windows, address bar, devtools), so the browser does not save, print,
  open a file or go back."*
- Scaffold correction applied: "0 downloads" also counts File System Access picker calls; the control
  shows why (Ctrl+Shift+S produces a picker call and 0 downloads).
- **Plan correction, §2.3.3 "Delegated while the text editor is focused and its lease is granted"**
  (and open item 1). "Every key except the mind-map keys" is wrong: the textarea's own handler zooms,
  changes the font size, submits, indents and saves (its save test ignores Alt). Proposed row: *"Keys
  without Ctrl, Cmd or Alt; caret moves (Alt only on macOS); Ctrl/Cmd/Alt+Backspace/Delete; Ctrl/Cmd+Z,
  Ctrl/Cmd+Shift+Z, Ctrl+Y; Ctrl/Cmd+A; Ctrl/Cmd+C, X, V, Shift+V. AltGr and Option characters are typed
  by the browser with their keydown stopped. Every other chord with Ctrl, Cmd or Alt is stopped and
  prevented, whatever the other modifiers."* Open item 1 is closed by that rule, not by blocking named
  save chords.
- **Plan correction, §2.3.3 "Delegated to Excalidraw" (fix round 2).** The row must be decided the way
  Excalidraw decides, not by the physical key: a Ctrl/Cmd chord is delegated only when Excalidraw's own
  key tests (key where they read key, code where they read code, its CTRL_OR_CMD) pick exactly one
  delegated action and no earlier handler (key `?`) claims it. On German layouts that makes Ctrl++ bring
  forward (Excalidraw's behaviour), and on macOS Excalidraw's own Cmd+Option+[ ] does nothing in
  0.18.0-1118751 (two keyTests match); Lobby either accepts that or owns z-order and zoom itself.
- **Also changed in fix round 2 (Lobby-owned keys):** Ctrl+F, Ctrl+Z / Y, Ctrl+A and the browser-chord
  list are read from the layout's character (a Latin `key`, else `code`) instead of `code` or `key`, so
  a layout's Ctrl+T reaches the browser and Lobby's search follows the letter printed on the key.
