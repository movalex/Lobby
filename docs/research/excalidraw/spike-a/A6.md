**Status: PASS, after a correction** (fix `f17ce48`; 3 of 3 runs of the old and the new A6 specs, see
"Runs after the correction"). Windows 11, Node 24, Playwright 1.63.0 headless Chromium shell, engine

Plan §8.2 A6 (with revision 3.1 open item 1): *the key allowlist (§2.3.3) in edit mode: every

## Correction (2026-09-29): the first version did not close open item 1

The first version of this check (code `5f49521`, merged as `5203e41`) passed its literal criterion, and
the report said "Lobby's capture listener closes this". **That was wrong.** Inside a granted text editor,
its rule was "delegate every key except Ctrl/Cmd+S and Ctrl/Cmd+Shift+S", and its save test
(`isSaveChord`) required `!altKey`. Excalidraw's save key test ignores Alt. The independent verifier
showed that Ctrl+Alt+S inside a granted editor calls `showSaveFilePicker` and closes the editor, 20 of 20
times, and Cmd+Alt+S does the same under macOS emulation.

The same rule let the textarea's other actions through as well. On the unfixed code (`5203e41`, with the
new regression spec), the sweep of 658 chords per platform found:

| Chord (Windows; under macOS emulation the same with Cmd) | What Excalidraw did |
|---|---|
| Ctrl+Alt+S, Ctrl+Meta+Alt+S (macOS: Cmd+Alt+S, Ctrl+Cmd+Alt+S) | `showSaveFilePicker` (the whole board), editor closed |
| Ctrl+= and Ctrl+- (also with Meta and/or Alt) | canvas zoom and scroll changed (8 presses) |
| Ctrl+Shift+, and Ctrl+Shift+. (also with Meta and/or Alt) | the label's `fontSize` changed, and `currentItemFontSize` (8 presses) |
| Ctrl+P (and Ctrl+Meta+P) | a toast (two later rows, Ctrl+Meta+H and Ctrl+Alt+G, record only that the toast field changed again: most likely the toast expiring) |
| Ctrl+[ and Ctrl+] (any extra modifiers) | the text indented or outdented (a label-text change, allowed by the metric, but Excalidraw acted) |
| every non-kept chord | reached the textarea's handler: 637 of 658 presses on each platform |

The fix makes the rule inside the editor an allowlist. The new spec fails on `5203e41` (Windows and
macOS sweeps: 637 of 658 presses flagged each, 2 picker calls each; the macOS kept-key test: Cmd+Alt+S
was delegated and saved) and passes on `f17ce48`.

it returns for a writable target (44005-44011). Ctrl/Cmd+P is blocked; Ctrl/Cmd+V is kept (the flag is
harmless and the paste itself is an event).

## The corrected rule (`keymap.ts`: `classifyTextEditorKey`, `isKeptTextEditorChord`)

**Kept (delegated to the textarea):**
- every key without Ctrl, Cmd or Alt: typing, dead keys and IME keys, Enter, Shift+Enter, Tab and
  Shift+Tab (Excalidraw indents), Escape, arrows, Home/End/PageUp/PageDown, Backspace, Delete. In this
  class the textarea's handler acts only on Escape and Tab, both kept;
- caret and selection moves with Shift, Ctrl or Cmd (arrows, Home, End, PageUp, PageDown); with Alt
  only on macOS (Option word moves). On Windows and Linux Alt+Left/Right/Home are the browser's Back,
  Forward and Home page, which would leave the board, so they are blocked and prevented;
- Backspace and Delete with Ctrl, Alt or Cmd (word and line deletes);
- Ctrl/Cmd+Z and Ctrl/Cmd+Shift+Z, and Ctrl+Y: the textarea's native undo and redo;
- Ctrl/Cmd+A: selects the text;
- Ctrl/Cmd+C, X, V, Shift+V and Ctrl+Insert: the clipboard arrives as copy, cut and paste events, where
  the export-policy listener applies.

A kept chord needs exactly one of Ctrl and Cmd and no Alt. Letters are read from `key` when it is a Latin
letter and from `code` otherwise, so Ctrl+Я is still Ctrl+Z. A unit test mirrors every branch above and
checks, over 77 keys x 16 modifier combinations on both platforms, that no delegated key triggers a
textarea action except Escape and Tab/Shift+Tab, and that the only delegated letter, digit or
punctuation chords are Ctrl/Cmd+A, C, X, V, Shift+V, Z, Shift+Z and Ctrl+Y.

**Typed by the browser, keydown stopped (`browser` verdict: stopPropagation, no preventDefault):** an
AltGr character (Windows reports AltGr as Ctrl+Alt; `getModifierState('AltGraph')`, now read through
`keyLikeOf`), a macOS Option character, and a key while an IME composes (keyCode 229). Excalidraw's
handler never sees these keydowns, so an AltGr+S that reports `s` on a layout without an AltGr
character cannot save.

**Blocked (stopPropagation, and preventDefault except the browser chords: reload, tabs, windows,
address bar, devtools):** every other chord with Ctrl, Cmd or Alt, whatever the other modifiers.

## The regression spec (`host-a6-editor.spec.ts`)

- **Sweep, Windows and macOS emulation** (`navigator.platform = 'MacIntel'` before load, so Excalidraw's
  CTRL_OR_CMD is `metaKey`): one note, its editor opened through Lobby (click, Enter, grant after 30 ms),
  `abc` typed. Then every letter (26), digit (10) and punctuation key (11: `` ` - = [ ] \ ; ' , . / ``)
  with each of the 14 combinations of Ctrl/Meta/Alt/Shift that include Ctrl, Meta or Alt: 658 presses.
  After each press (two frames + 40 ms) the spec requires: 0 File System Access picker calls
  (instrumented), 0 downloads, 0 dialogs, 0 popups, 0 new pages; no element change except the label's
  text and layout fields (and its container's fit); no change in 30 appState fields; the same textarea
  node still open, focused and in phase `open`; a kept chord reached the textarea, every other chord did
  not (a target-phase listener on the textarea counts it). A press that closes the editor is recorded and
  the editor is reopened, so one failure does not hide the next.
- **Kept keys, Windows**: Ctrl+Backspace, Ctrl+Z, Ctrl+Y, Ctrl+Shift+Z, Ctrl+A, End + Ctrl+Left,
  Shift+Home, Ctrl+Delete, Ctrl+C / End / Ctrl+V, Tab, Shift+Tab, Shift+Enter and Enter each do what the
  browser or Excalidraw's indent does (value and selection checked), every one is `delegate`, and the
  label stores the final text.
- **macOS verdicts**: Cmd+Z, Cmd+Shift+Z, Cmd+A, Cmd+C/X/V, Cmd+Backspace, Option+Backspace,
  Option+Left and Cmd+Right are delegated; Option+E and Option+S are left to the browser; Cmd+S,
  Cmd+Alt+S, Ctrl+Alt+S, Cmd+=, Cmd+Shift+., Cmd+Enter, Cmd+] and Cmd+Y are blocked; 0 picker calls;
  the editor stays open. (Windows Chromium does not run the Mac editing commands, so this test checks the
  verdicts, not their native effect.)

## Lobby's Ctrl+A

Scene: a 2-rectangle group, a locked rectangle, a rectangle marked hidden (mind-map collapse), a note
with a label. Lobby's Ctrl+A selects `g1a`, `g1b`, the note (not its label, not the locked one, not the
hidden one) and the group `grp`, with 0 element changes; Excalidraw's own select-all (control) also
takes the hidden element. Excalidraw expands selected groups to every live member, locked ones and
labels included, and drops groups with fewer than 2 members (element dist/dev/index.js 12228-12290);
`selectAll.ts` mirrors that and never adds a hidden member.

## Deviations from the plan

- The plan's row says "stopPropagation"; the spike also `preventDefault`s blocked chords (see above).
  Proposed addition to §2.3.3: *"Blocked keys with Ctrl, Cmd or Alt are also `preventDefault`ed, except
  browser chords (reload, tabs, windows, address bar, devtools), so the browser does not save, print,
  open a file or go back."*
- Scaffold correction applied: "0 downloads" also counts File System Access picker calls; the control
  shows why (Ctrl+Shift+S produces a picker call and 0 downloads).
- **Plan correction, §2.3.3 "Delegated while the text editor is focused and its lease is granted"**
  (and open item 1). "Every key except the mind-map keys" is wrong: the textarea's own handler zooms,
  changes the font size, submits, indents and saves (its save test ignores Alt). Proposed row: *"Keys
  without Ctrl, Cmd or Alt; caret moves (Alt only on macOS); Ctrl/Cmd/Alt+Backspace/Delete; Ctrl/Cmd+Z,
  Ctrl/Cmd+Shift+Z, Ctrl+Y; Ctrl/Cmd+A; Ctrl/Cmd+C, X, V, Shift+V. AltGr and Option characters are typed
  by the browser with their keydown stopped. Every other chord with Ctrl, Cmd or Alt is stopped and
  prevented, whatever the other modifiers."* Open item 1 is closed by that rule, not by blocking named
  save chords.
