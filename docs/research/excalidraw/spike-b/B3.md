## L10 5, "B's move first" (M1/M2 first run: 20/20 lost, then 80/80 kept): cause, trace, fix

**What the lead saw** (`scratchpad/int/checks1/b3-l6-l10-arrows.log`, `2a1944e`, a loaded machine): B's
move of a centred free text T lost in all 20 "B's move first" rows (the stored `y` back at A's old value
and the centre at A's), and kept in all 80 rows of the rerun at `9b6fb7e`. The lead's reading: while A's
fit is in flight, `rebuild` keeps the fit's local `x`, `y` over the server's copy, and `staleFit` drops
only an unsent fit.

**Confirmed, and made deterministic.** The rows that fail are the ones where A's race typing spans more
than one typing push (`TYPING_PUSH_MS` = 500 ms): on a loaded machine the 19 keys of `' centred text grows'`
take longer than 500 ms; on a quiet one they fit in one push, and a single in-flight fit is handled right.
The spec now has a variant **`5-slow-typist`** (the same race, 90 ms between A's keys, so 4 typing pushes)
and records A's side of every race (`trace.a`: A's pushes of T with seq, base and fit; its acks with the
commit clock; its refits; the core's `fit_superseded` records). Before the fix (`engine.ts` of `76c937f`,
the spec and the rest as committed in `18254dd`; `SPIKE_B3_L10_VARIANTS=5-slow-typist SPIKE_B3_ARROW_REPS=5`, base 7870): **B's move
first 0/5, A's fit first 5/5**. One failing row's trace (B's move committed at clock 49):

```
A's pushes of T   seq 44 base 48 fit {x: 4926.1}   seq 45 base 48 fit {x: 4898.2}   (sent before B's move reached A)
                  seq 46 base 49 fit {x: 4873.4}   seq 47 base 49 fit {x: 4860.3}   (base 49 = B's move included,
                  seq 48 base 50 ...  seq 49 base 51 ...                             x computed on A's OLD position)
A's events        refit, ack 44 -> 50, refit, ack 45 -> 51, refit, ack 46 -> 52, ack 47 -> 53, ...
stored centre     4923.6, B's intended 5080 (lost); y kept in these rows
```

Pushes 46 and 47 carry fits computed on A's old position but with a base that includes B's move, so the
room applies them (`merge.ts`: a fit applies when `gclock.pos <= base`) and B's move is undone. A's scene
never took B's position: every `changes` and ack rebuilt T with the local `x`, `y`, because a fit was in
flight or dirty at each of them, and each `fitDropped` ack's refit shifted the stale local copy again. The
`y` goes too when an ack finds a dirty fit and no other fit in flight (then the next fit is built against
the server's `y`): acks bunched by a loaded relay make that likely, which is the lead's 20/20.

**Fix** (`18254dd`, `engine.ts` `placedByOther`, replacing `staleFit`): a server write to the position of a
free text this holder fits (to a container: its position or size) that is not this client's own applied
fit (recognised by its values) supersedes every fit of this client not applied yet, in flight or dirty,
at once: their fields leave the in-flight records (so `base` and `rebuild` take the server's position
immediately), the dirty fit is dropped, and one refit re-applies their combined shift since the server's
copy before the write (a free text: `dx`/`dy`; a container: its layout re-runs). Their later `fitDropped`
acks ask for nothing more. After the fix the same slow-typist rows show one `fit_superseded` per race
(e.g. `{inflight: [149, 150], dirty: true, fields: [x, y], dx: -59.5}`) and every later push's fit
computed on B's position (e.g. seq 151, base 184: `x` 948.6, centre exactly B's 1080).

**Tests.** Core (`core/engine.test.ts`, fail before, pass after): "L10 5 (B's move first): fits of A's still
in flight when B's move arrives never undo it…", "…a slow typist: A types through every ack…", and "L6/L10 1:
a container fit in flight when B's resize arrives: the scene takes B's size at once, one refit, B's size
kept"; plus "L10 5 (A's fit first): an own applied fit is not a remote move…" (a guard, passes before and
after). Browser: L10 3-5 with all three variants at 5 repetitions: **30/30** (base 7870); the whole L6/L10
spec at 5 repetitions: see the smoke runs below.

## Deviations

- **Part 2 additions (stricter, not weaker):** L10 3-5 has a third variant, `5-slow-typist` (L10 5 with 90 ms between A's race keys, so A's typing spans several pushes: the case the M1/M2 first run met on a loaded machine), with the same pass conditions in both orders; `SPIKE_B3_L10_VARIANTS` selects variants for a repro run only (a filtered run is never the check's evidence). Every L10 5 row records A's pushes, acks, refits and `fit_superseded` records (`trace.a`). `waitSaved` reports the core's bookkeeping when it times out.
- **Not the quiet window.** Part 1: one run, L6/L10 at 5 repetitions per variant and order (the plan says 20). Part 2: L6/L10 again only as 5-repetition smoke runs; every other B3 check ran its full count 3 times. The 20-repetition L6/L10 runs and the timing-gated L1 and L5 belong in the lead's quiet window.
- **L6/L10 gestures are Excalidraw's own element operations, not pointer drags**: `editTarget` (mutateElement + updateBoundElements, as a resize leaves the scene), `dragPoint` (createPointAt + movePoints), `dragSegment` (moveFixedSegment), `dragFrame` (dragSelectedElements), `rotateSelection` (the rotation handle's writes), run on a copy of the scene and installed as one local edit through `CanvasPort.transact`, so the engine core sees what a gesture's end leaves (the arrows' follow included, held as derived). A types for real. The commit order is forced with the latency relay on the side that must commit second and **verified** from the acks' commit clocks (the row's `committed` equals the intended order).
- L6/L10's server half (the room's log of fit writes, `gclock.fit` of derived rows) is O1's and not read here; the client half checks that A and B push no arrow ops and that every arrow ends on its target's edge (Excalidraw's own follow re-run on each map, within `GEOMETRY_TOLERANCE_PX`).
- L6 3b: a self-loop's midpoints move with its start (Excalidraw's `moveMidPointsWithElement`), so C's midpoint is checked relative to the arrow's start.
- L10 5, order "A's fit first": B's write (an absolute `x` from B's copy) lands on the already grown text, so the centre is not B's intended one; it lies between the two bounds the spec checks (B's intended centre and B's `x` plus half the final width). In the other order (B's move first, A's fit dropped and redone) the centre is exactly B's.
- L6 3e: the earlier writer undoes first (skipped as changed while the later version is stored), then the later writer (applies).
- L9: the §2.9.2 caret: Lobby-initiated opens replay at the end; a guard-caught double-click on the label keeps Excalidraw's select-all, so the buffered keys replace the text (as with an instant lease, plan line 157); P5 keeps the click point.
- L13: CDP has no AltGraph modifier, so the AltGr keydown is an in-page `KeyboardEvent` with `modifierAltGraph` (checked: not prevented, never reaching the textarea's handlers) followed by the browser's default action as `Input.insertText`; Option+S is a real CDP key event carrying 'ß'. No German keyboard or Mac was used.
- L12 and L9 run on the real board with the room's lease hook (delay 300 ms, hold, release); the guard monitor is host-lab's A6/A16 monitor ported to the board page.
