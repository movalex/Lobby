## How the check runs

Four headless Chromium processes on one board of a real stack (`DRAFTROOM_BACKUP_STORE=off`): the editor (the board's owner), a commenter and a viewer (members at those roles), and a **limited guest**: a name-only guest let in by a view link with guests allowed, which makes the api limit exporting to editors on that board (DANA2-01). Each process counts, from before the board loads: File System Access picker calls (`instrumentFilePickers`, each rejected as a Cancel), `window.print` calls and clipboard API writes (both replaced by counters, so nothing reaches the machine's clipboard or a print dialog), and Playwright's download, dialog, file chooser and popup events (`watchPage`).

Per repetition and role: a rectangle is selected, the canvas focused, and the plan's keys pressed: Ctrl+S, Ctrl+Alt+S, Ctrl+Shift+S, Ctrl+O, Ctrl+P, Alt+Shift+C, Ctrl+Shift+E, Ctrl+/, Ctrl+Backspace, Tab, Shift+Tab, Q, Shift+X, Ctrl+ArrowRight, Ctrl+ArrowLeft, G, S, I, and the digits 1–0. Then a copy (a synthetic `copy` event with its own DataTransfer, as the browser's Ctrl+C sends it, so the machine's clipboard is never touched) and a file drop (`dragover` + `drop` with a text file on the canvas).

Pass: 0 downloads, 0 picker calls, 0 file choosers, 0 dialogs, 0 popups, 0 prints; the page's map hash unchanged and 0 pushes after the keys; the drop's default prevented for every role, and no element change from it for the read-only roles; copy: the editor's copy carries Excalidraw's clipboard data (the positive control), no read-only role's does.

## Product defect found by R3

- **An editor could not copy or paste with the keyboard.** Outside the text editor, the allowlist classified Ctrl/Cmd+C and Ctrl/Cmd+V as "block" with `preventDefault`, so the browser never fired its `copy` / `paste` event, which is where Excalidraw copies and pastes (X 49346) and where Lobby applies the export policy (plan §2.3.3: "the allowlist does not block them"). Fixed in `c48e35c`: for editors they are stopped before Excalidraw's keydown and left to the browser (`{kind: 'browser'}`); Ctrl+X stays blocked (Excalidraw's `actionCut` has a keydown keyTest, spike A A6); read-only roles are unchanged (blocked; their copy/paste events are stopped by Lobby's policy anyway). Unit tests in `input/keymap-verifier.test.ts` ("spike B R3") fail before and pass after.

## Deviations

- "Limited viewers cannot copy": the spike board page applies CanvasInput's default ("copy: editors only") to every read-only role; it does not read the board's export policy from the ticket. So the check shows that no read-only role, limited or not, can copy.
- The limited guest's browser is launched as a dev user, signed out and let in through the guest invitation (the harness's `launchBrowser({guest: true})` is not available yet).
- The copy is a synthetic `copy` event; the keyboard path to it (Ctrl+C for an editor → `browser` verdict → the browser's copy event) is pinned by the unit test, not by this spec, so that no spec run writes the machine's clipboard.
