### The mind-map collapse prototype (§4.7)

Only `collapsed` is stored, on the parent topic's `customData.lobby.mindmap` (one `transact` step). Every
client computes the hidden branch from the scene (`features/model.ts` `mindmapHidden`: every descendant
topic and every edge into one) and hands it to the board page's one `RenderOverrides`
(`overrides.ts`, which expands labels and frame children). The same set feeds the hit guard,
`registries.hidden.isHidden` (O2's Ctrl+A and box/lasso post-filter), the guard's own selection
post-filter and exports (`export/select.ts`). No element but the parent is ever written ("opacity 0 +
locked" is not used).

`b12-collapse.spec.ts`: A collapses through the chevron; A and B compute the same four hidden ids; the
overrides name the leaves' labels too; B's pixel at a leaf is background; a click and a double-click
there do nothing (no selection, no editor); Ctrl+A selects everything else and none of the hidden items;
a box over the whole map is post-filtered; the SVG export carries the visible labels' text and none of
the hidden ones'; B pushes 0 ops; converged; the stored `collapsed` is true; expanding restores the pixels.

### The hit guard's gaps (§2.7)

Built in `canvas/overrides.ts` (the dead zone, the hover cursor, touch), with `installBoardOverrides`
providing `registries.hitGuard.isBlocked` and `registries.hidden.isHidden`, and naming the dragger
through O2's `registries.dragger.draggerOf`.

| Gap | Rule | `b12-guard.spec.ts` |
|---|---|---|
| Hover cursor | a passive `pointermove` test (one per frame, only while something is hidden or previewed, never while a button is held) toggles `lobby-hit-blocked` on the wrapper; `.lobby-hit-blocked canvas.interactive { cursor: default !important }` beats Excalidraw's inline cursor (App.cursor.set, dist/dev/index.js 27988-27991) | computed cursor `default` over a hidden leaf and over the document spot of a note B is dragging (B holds the mouse down); the class is off over a visible topic |
| Touch | the guard's `pointerdown` runs for touch and pen; a one-finger `touchstart` is swallowed (Excalidraw's own double-tap detector never sees it); the long-press menu is armed inside Excalidraw's `pointerdown` (maybeOpenContextMenuAfterPointerDownOnTouchDevices, 45941-45955), so it never arms; `contextmenu` swallowed | T (touch): tap, double-tap (80 ms apart), CDP long-press (900 ms) on a hidden leaf: no selection, no editor, no lease pending or held, no context menu, 0 pushes; a tap on a visible topic still selects it |
| Dead zone | a swallowed press runs Lobby's own hit test skipping hidden and previewed elements and selects what it finds through `appState` (selection only); "Bob is moving this" (`[data-lobby-hit-toast]`) for a previewed element | U under M; B drags M and holds; A clicks the old spot where U shows: A's selection is `[U]`, the toast says "Bob is moving this" |
| Sibling over the branch | the same rule | A2 (sorted below the leaves) moved over Leaf one; B's click there selects A2; converged, 0 violations |

## The mind-map collapse decision for wave 3d (to be confirmed by the runs)

Recorded now from the build; the three runs add the numbers (hidden ids, labels, Ctrl+A and box counts,
SVG bytes) and confirm or change it.

1. **Keep the prototype's model**: `collapsed` on the parent's `mindmap` value, the branch computed by
   every client, hidden with the render override. It needs no write to anyone else's element, survives
   "Unlock all" and real locks, and undoes as one step.
2. **The guard carries the rest**: the hit guard (clicks, double-clicks, drags, menus, touch), the cursor
   rule, `isHidden` for Ctrl+A and the box/lasso post-filter, and the export filter. Search, copy and the
   accessibility list must consult `registries.hidden` the same way (wave 3d).
3. **Layout keeps the collapsed branch's area free: recommended**, although the dead-zone rule makes a
   sibling over the branch clickable. Without it, the hover cursor over the sibling is still forced to
   `default` wherever the hidden branch lies above it in z-order (the hover test reports the element
   Excalidraw would pick), and the first click selects rather than drags. Keeping the area free avoids
   both; +0.5 pd in 3d as §4.7 estimated.
4. **Cost to watch**: the hover test and `isBlocked` run Lobby's own hit test over every element
   (`elementAtScenePoint`, O(n)); it runs only while a branch is hidden or a preview is active, once per
   frame. On the heavy board (9k elements) this is unmeasured; O3's §8.4 numbers should include a hover
   sweep with one branch collapsed.
