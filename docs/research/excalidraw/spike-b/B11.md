## What the spec does

Three Chromium processes and 50 headless clients (O2's engine core, loaded through `e2e/load/headless.ts`)
run random ops for 10 minutes. Each headless client is a dev user with a grant, and every connect uses a
fresh 60 s api ticket.

**Browser ops**, through the facade or the keyboard:
- create a note;
- move, recolour, group (own elements);
- delete;
- text through the lease (select, Enter, type, Escape);
- Ctrl+Z;
- bind: an arrow between two own notes, as engine fields with `startBinding`/`endBinding`.

**Headless ops**, on the client's scene with Excalidraw's version bump:
- create (`buildStickyNote`);
- move, recolour, group;
- delete;
- label text.

The headless client has no undo stack, so undo is a browser op only.

**Disruptions:**
- Every 45–90 s, either a browser's socket is cut for 3–8 s (the relay), or a headless client is
  dropped and replaced after 3–8 s.
- Once, at a random minute in [3, 7], sync gets a SIGKILL and is restarted 3 s later.

**Pass conditions:**
- After a final quiesce (every tab shows Saved and every client is saved), all 53 maps hash equal to the
  test snapshot, tombstones included (`closeWindow`, with its horizon check).
- 0 invariant violations.
- 0 acked-but-missing. Each client changes only elements it created, and keeps a ledger of their
  tracked fields (`x`, `y`, `backgroundColor`, `isDeleted`, `groupIds`) as last acked:
  - headless clients record from their acks;
  - browsers record every 2 s while the tab shows Saved, which means everything so far is acked.
- The acked-but-missing comparison runs right after the restart, once every client is back. An element
  is compared when its ledger entry predates the kill and its writer did not push it again before the
  kill. Such an element must be stored exactly as the ledger says. The number of elements checked is
  in the evidence.

## Deviations from the check as written

- **Undo:** browsers only (the headless client has no stack).
- **Bind:** only between a client's own notes, so an arrow's targets have a single writer.
- **Acked-but-missing:** covers the elements whose state was settled at a Saved moment before the kill.
  An element pushed in the last moments before the kill is left out of the count and not compared.
- **The kill replaces every headless client.** After the SIGKILL and restart the spec drops and
  reconnects all 50 headless clients (fresh cores, fresh tabs), so a create a client made while sync was
  down, never acked, is lost with its old core. That is why a run stores about 40–60 fewer
  headless-created elements than the clients made (never acked, so not acked-but-missing).

## Results

`bash docs/research/excalidraw/spike-b/scripts/o3-checks.sh b11 3` (base 7880, a fresh build each run,
not a quiet window: other owners' stacks ran on the machine). Logs and evidence JSON in O3's scratchpad
`o3b/runs/<utc>/`.

### Void: the first pass at `75fe4d5` (15:40–16:13Z), and the lead's first run

3 runs "passed" (10.6–11.4 min each; 1,044 / 1,067 / 1,085 browser ops; acked-but-missing 0 of 69 / 70 /
134 checked). **Not counted:** every headless op threw `ReferenceError: document is not defined`.
`buildStickyNote` measures the note's label, which in Node needs the server's text metrics
(`installServerTextMetrics`, which the room and `e2e/load/boards.ts` install and the spec did not). With
fewer than 3 notes of its own a client's op is always a create, so all 50 clients failed on every op
(about 14,900 attempts per run), and the errors went only into a 20-line sample of the evidence. The
lead's M1/M2 run of the same spec (10.7 min, PASS) had the same defect. Fixed in `03df2c1`: the spec
installs the metrics, counts every op that threw and every applied op, and **fails unless no headless op
threw and the snapshot holds headless-created elements**. A 60 s dry run with 10 clients then made 300
edits with 0 errors.

Run 1, the first run in which the headless clients really wrote: after the final quiesce, 52 of the 53
maps (B, C and all 50 headless clients) hashed equal to the test snapshot; **browser A did not**, while
it showed Saved. `explainDivergence`: one element, `note-jnu1bv84oni`, differed in `version`,

one, nothing dirty, nothing in flight. The run's trace is in O3's scratchpad; the spec wrote no more
than the ids and keys, so it now writes more (next pass). Not reproduced since (5 runs). Reported to
the lead for O2 (the engine core decides what a Saved tab holds; an index-only difference points at the
index pre-pass or the re-key path of `applyScene`); V1's B11 slice should try to reproduce it.
