## 1. What the ported feature does

One `CanvasFeature` (`ported/index.tsx`), with the tldraw feature's behaviour and copy:

- **Top bar** (`topBar` entry `workshops`, order 25 since wave 5, before Present and export as on the tldraw
  page; overflow caption "Timer and voting"): the timer pill and
  its popover (presets, duration, start/pause/resume/+1/+5/stop, "is running this timer" for someone
  else's, sound on/off), the vote chip, the private brainstorm chip, the raised-hands chip and queue, the
  reactions bar with raise hand, "Gather everyone", and the session settings.
- **Dock panels** (orders 40 and 45 since wave 5: after Comments and the navigation panels, before History):
  `voting` (the current vote, facilitator progress and controls, the ranking with "See all",
  the CSV, past votes) and `private-notes` (prompt, counts, my notes with edit/delete, the phone timer,
  reveal / Place notes / cancel, where the notes went).
- **Overlay layers** (`featureOverlays`, all `focusMode: 'show'`): `workshops-marks` (scene, order 15: the
  revealed counts, grouped when zoomed out), `workshops` (scene, order 249: my dots, the +/- stepper, +1s, the
  message stack of follow notice / brainstorm card / results card / join prompt / voting bar), `workshops-top`
  (screen, order 10001: the time's-up flash, the floating timer while presenting or on a phone, the raised
  hands while presenting, reaction bursts, hand toasts). Layers keep the tldraw CSS (`workshops.css`).
- **Voting on the canvas**: with the select tool, a plain primary press on an object the vote accepts is
  claimed on the input stream (`canvas.on('input')`, `handled()`), so the engine never selects it, and votes
  on release; a double-click on it is one vote and never opens its editor; the hand tool pans and its clicks
  vote. The `vote` pointer tool (`tools`, `readOnlyAllowed`) votes the same way. Since wave 5 (W5-03) the
  topmost object under the press decides (the hit test takes no filter): one the vote does not take casts
  nothing and says "Not part of this vote: only … take votes."; the press goes to the engine as usual. Keyboard (RETRO-06): Tab
  from the board into the selected object's stepper (or to the first object), Enter/Space, Tab to the next.
- **+1** (`ported/plus-ones.ts`): the identity-bound `customData.lobby['plusOne:<uid>']` key, one `transact`.
- **Session settings** (`ported/session-settings.ts`): lb_doc `workshop` through `canvas.doc.set`; "Hide note
  authors" sets `html[data-dr-hide-authors]`; "Hide everyone's cursors" provides `registries.cursorVisible`.
- **Private brainstorming** (`ported/private-notes/**`): the setup dialog (selected frame or a new "Private
  ideas" frame in free space), the panel, the start card and phone reminder, the end notices.
- **Gather everyone**: the summon event starts 3c's `canvas.follow.start(sid)` on the summoner's session.
- **Exports**: `provideVoteResultsForExport(canvas, …)` (`vote-export.ts`) as on the tldraw board.

### For other owners

- **3e (present-export)**: read the session settings with `workshopSettingsOf(canvas)` from
  `features/workshops/ported/session-settings.ts` (exports drop note authors; present mode may hide
  cursors), and the revealed results with `voteResultsForExport(canvas)` (`features/workshops/vote-export.ts`,
  keyed by the LobbyCanvas). Present mode on this page is recognised by the canvas's focus mode or
  `html[data-dr-presenting]`. The cursor filter: see CR-3F-5.
- **3c (follow)**: the feature calls `follow.start`, `follow.current`, `follow.stop` and `on('followChanged')`,
  and ends following on a plain canvas press (as the tldraw board did). Its follow notice says "use Stop
  following at the top left": that is where tldraw's own button was; the copy should follow wherever 3c puts
  its button (one button, RETRO-11).
- **3a (keyboard map)**: the feature declares no chord statically. Tab is registered in `registries.keys` only
  while this person votes (as the tldraw board's capture listener existed only then).
- **3i (phone sheet)**: `setTool('vote')` gives a phone a voting tool that never selects.

## 2. Deviations from the tldraw board

| # | What | Why |
|---|---|---|
| D1 | A locked note shows its +1 count but no +1 control. | The sync server refused every `customData` change of a locked element (`LOCKED`, room `merge.ts` step 5), +1 keys included; the tldraw board wrote +1s past the lock. CR-3F-2. **Wave A: done** — the lock rule lets the writer's own `plusOne:<uid>` through as a partial accept, like `z` (registry flag `lockExempt`; `lock-exempt-keys.test.ts`, `locked-customdata.spec.ts`), and `PlusOnes` shows the control on a locked note. |
| D2 | A +1 is an undo step. | `LobbyCanvas.transact` was always one undo step; tldraw wrote +1s with `history: 'ignore'`. CR-3F-1. **Wave A: done** — `TransactOptions.skipUndo` keeps a write out of this tab's undo history; `ported/plus-ones.ts` passes it (`plus-ones.test.ts` asserts `{ skipUndo: true }`; the `workshops-facilitation` `test.fail` is gone). |
| D3 | +1s are per-person keys: no intent list, and their order is by uid. | Per-key `c:` patches never meet (tldraw re-applied appends the server dropped); the value is `true` to fit 200 in the budget, so arrival order is not stored. |
| D4 | No text fit after a reveal. | The server lays placed notes out with Excalidraw's own code and its text metrics (room-internal `place-notes.ts`); the revealing tab only waits for them and shows them. |
| D5 | The "Private ideas" frame is made after the session starts, under an id chosen before it. | `customData.lobby.privateFrame {session, by}` is create-only and names the session. A failed start leaves nothing (tldraw made the frame first and deleted it again). |
| D6 | Placed notes are found by `customData.lobbyServer.privateNote.session`, authors by `lobbyServer.createdBy`. | canvas-schema's server-owned class (plan §3.3), not `meta.drPrivateNote` / `textLastEditedBy`. |
| D7 | A `vote` pointer tool exists (no toolbar button). | The contracts' tools registry lists it for 3f; clicking with the select or hand tool votes as before. |
| D8 | The Tab key is not in `collectKeyClaims(CANVAS_FEATURES)`. | It is registered only while voting (the tldraw board's listener existed only then; Tab is in no shortcut table, and a static claim would collide with the mind map's Tab in 3a's keyboard-map test). |
| D9 | Camera moves use 3b's `viewport.zoomTo` / `ensureVisible`, or `viewport.set` while those are stubs. | Rule 10 (call the member); the fallback keeps the feature whole until 3b's part lands (`ported/camera.ts`). tldraw's `targetZoom` is the fit capped at it, as 3b's `maxZoom`. |
| D10 | "Gather everyone" tells the summoned person "…isn't available here yet" until 3c's follow is in; the readable phone zoom while gathered (R2-04) is not ported. | Follow is 3c's; the readable zoom needs a hook in their follow camera. CR-3F-3. **Wave 3b (3CF): done** — `follow.start(sid, {camera})` (W3-10) and `ported/camera.ts` `readableFollowCamera`; the summon carries the summoner's canvas size (`SummonScreen`), from which a follower reads the leader's zoom (their canvas height over their view's height). |
| D11 | The Voting panel's CSV gate reads the export policy itself (`ported/export-gate.ts`: GET export-policy, the `export-control.policy` event, resync, role, guest kind). | The tldraw store is tldraw atoms fed by sharing's overlay (3e's port). Switch to 3e's ported store once it exists. |
| D12 | "Hide everyone's cursors" re-provides the cursor filter while on, whenever another provider took the slot or let it go. | `cursorVisible` has one provider; present mode (3e) needs it too. CR-3F-5. |
| D13 | "Hide note authors" has nothing to hide on this page yet. | The Excalidraw page draws no note-author label (tldraw's note face did). CR-3F-4. **Wave 3b (3CF): done** — the workshops feature (the one that draws overlays on notes) owns the label: the `workshops-authors` scene layer (`ported/NoteAuthors.tsx`, `note-authors.ts`) draws the first name of the label's `lobbyServer.lastEditedBy` in each note's bottom right corner, not under opaque elements painted above it or outside its frame, and nothing while "Hide note authors" is on. No hover tooltip (the layer takes no pointer events); exports never carry it. |
| D14 | Objects are named by `shape:<elementId>` only for ids the workshop api can name (`VOTE_SHAPE_ID_PATTERN`: no `.` or `:`). | The api's vote and brainstorm refs use that pattern; the element id pattern is wider. |
| D15 | Presenting = the canvas's focus mode or `html[data-dr-presenting]`. | Present mode on this page is focus mode (contracts §3). |
| D16 | The private notes panel's swatches still come from `features/canvas-ux/palette.ts` (3a's file, a type-only tldraw import). | Its light fills equal the Excalidraw note fills (`board-ops` LOBBY_PALETTE); wave 4 moves it with 3a's port. |
