## Deviations (behaviour or copy that differs from the tldraw page, and why)

1. **Undo of a new topic takes two steps** (its words, then the topic): the words typed into a new topic are the editor's own step on Lobby's history; tldraw folded them into the topic's step. Folding them needs `LobbyHistory.mergeTop` (W1-9, recorded, not applied). `mindmap-keyboard.spec.ts` tests two presses.
2. **Typing on a selected topic does not start editing**: letters are the tool keys on this canvas (the key allowlist), so type-to-edit on a topic (tldraw's) is not claimed; F2 edits with the caret at the end, Enter adds a sibling as before. See CR-3D-3.
3. **The map follows a dragged central topic on the drop**, not during the drag (the keeper waits for the gesture so the drag stays one step; Lobby's writes during a gesture would cut it).
4. **An extra invisible undo step may appear** after a concurrent change or a drop: the engine's re-route of a bound elbow line lands on the stack as its own step (spike B history defect, CR-3D-4). The specs allow at most one extra press. The runtime replaces a line instead of rewriting it where it can, which avoids most of these.
5. **Toolbar "Mind map"** is the tool `mindmap` in the tool registry: 3a's toolbar activates it and the feature starts a map and hands the canvas back to Select. The spec uses `setTool('mindmap')` until 3a's toolbar is on the page. Asked of 3a: a toolbar *action* hook for tools that are buttons.
6. **Start from a sticky note** is tested through Alt+Shift+M (the same command as the context-menu entry) until 3a's context-menu shell is on the page; Present is tested as focus mode (3e sets it).
7. **Tag chips are in an overlay above every element**: a note lying over another no longer covers the lower note's chips, and a remote drag's preview moves the note before its chips (they follow on the drop, like the hit test, §2.7). tldraw drew chips inside each shape.
8. **"Show only" is a veil**, not per-shape opacity: the canvas colour at 86 % over everything except the carriers' rectangles (what tldraw's 0.14 opacity left). What overlaps a carrier shows through its hole; the others fade towards the canvas colour rather than becoming translucent.
9. **The board's tag list is lb_doc, which Lobby's undo does not cover**, so after an undo or redo of the elements the runtime brings the list in line with the elements' own copies (a missing definition is listed again, a name or colour the undo changed is written back). Undoing "Delete everywhere" and undoing a recolour therefore look as on the tldraw page. Two differ: undoing a tag's creation takes it off the elements and leaves it listed (tldraw's undo removed the list entry too), and undoing a rename puts the old tag back and lists it again while the new name stays listed, unused, until deleted.
10. **A name-only guest cannot create a tag**: the room refuses every guest's lb_doc write, so a new tag's definition never lands and the server refuses its `tag:<key>`. Guests on an editor link can still use the board's tags. CR-3D-5; `tags-panel.spec.ts` has the creation as `test.fail`.
11. **The picker opens in the tags screen layer**, placed under 3a's selection-bar button (or under the selection), not inside the bar; it re-places itself when the selection or the camera moves.
12. **File cards and chips**: the card placement is checked in the unit tests; the chips spec checks a shape (chips above it) instead, as creating a file card needs the media owner's upload path.
13. **Search by tag and the CSV tags column** are provided (`search.ts`, `SearchTagFilter.tsx`, `csv.ts`) but only used once 3b's search panel and 3e's export call them; the e2e test for both is skipped on this branch (it runs on the integrated tree when either part uses them). 3e's current CSV builds its own tags cell for notes and images only (not shapes or free text).

## Change requests

- **CR-3D-1 (proposed, `canvas/port-impl.ts`, spike-owned)**: a `transact` that creates an element and then updates it in the same transaction loses the update (the scene is built from the created elements as they were created: `...created` should be `created.map((e) => current.get(e.id))`). It also affects 2C's `tx.duplicate` label positioning. Worked around in `draft.ts` (writes folded into creation props; bindings in a second transact joined to the first's step).
- **CR-3D-2 (proposed, input / lease, spike-owned)**: the input stream's `input` events do not say which key-downs are synthetic (the lease opens a feature-created element's editor with a synthetic Enter), and during a pending lease no registry keys run. Asked: mark synthetic events, or a `pending` key scope for feature keys, and the "new element" lease fast path (`markCreated`) for elements a feature creates. Worked around with a trusted document-capture observer.
- **CR-3D-3 (proposed, 3a / input)**: type-to-edit on a selected mind-map topic: an allowlist rule like the single-note one, or a registry hook for "printable key on this selection".
- **CR-3D-4 (reported, spike B history, `canvas/history/**`)**: changes the server or the engine derives for bound arrows (re-routes, re-snaps) are recorded as undo steps of their own, and a rebind is recorded apart from its move.
- **CR-3D-5 (proposed, O1 room / contracts, `apps/sync/src/room/merge.ts` `applyDoc`)**: let editor-role guests write `tagDef:` doc keys (today every guest doc write is refused), so a workshop guest can create a tag as on the tldraw page.
- **W1-9 `LobbyHistory.mergeTop`** (recorded at wave 1): needed for deviation 1.
- **3a**: render the selection-bar item `tags` and the context-menu entries (`dr-tags-open`, the mind-map `organize` group); a toolbar action hook for `FeatureToolSpec`s that are buttons (deviation 5); the board's Delete could call the command `mindmap.delete` (whole branches) before its own.
- **3b**: the search panel can use `searchWithTags` / `SearchTagFilter` from `tags/ported/SearchTagFilter.tsx` (search by tag, MAK-12).
- **3e**: the CSV can use `tagsCsvCells` from `tags/ported/csv.ts` (all taggable kinds); the outline gate (`mindmap/ported/export-gate.ts`) should read 3e's export-policy store once both are on one branch.

No `CR:` commits: no frozen file was edited. No LobbyCanvas stub members were assigned to 3d. No test here is blocked by CR-2D-2 or CR 2F-2.
