## Deviations (behaviour or copy that differs from the tldraw page, and why)

1. **Fullscreen element**: the board's canvas region (`[data-lobby-board-canvas]`, which holds the overlay root), not tldraw's `.tl-container`.
2. **Present keys** are a modal window-capture trap while presenting (as on the tldraw page), not entries of the key registry: the registry has no "every key" claim, and n, Delete, Ctrl+Z, PageUp must do nothing. Only the Present shortcut is a registered command.
3. **Slide camera**: the presenter computes the fit itself and installs it with `viewport.set` (the same numbers draw the surround's window). `viewport.zoomTo` and `viewport.limits` are 3b's stubs; the zoom range is fixed at 0.02–8 (tldraw's was about 0.05–8 × its base zoom).
4. **Restore after a presentation** tracks the views it asked for: Excalidraw applies `updateScene` a render later, so reading the view straight back is stale. The canvas size comes from the region's layout (the engine's own copy lags a resize).
5. **Follow** (`follow.*`, 3c's stubs) counts as "nobody is followed" until 3c lands it; a follow that starts while presenting is stopped.
6. **Present to everyone** is 3c's feature (`present-live` in `CANVAS_FEATURES`): it plugs its chrome into the presentation through `ported/live-slots.ts` (`providePresentLive`) and drives it through `presenterOf(ctx.canvas)`. Until it does, there is no "Present to everyone" button (the Tab order has four controls, not five) and Exit always says "Exit".
7. **Frame names**: Excalidraw draws them above frames. While presenting they sit under the surround; in a whole-board PNG they add height inside the export (the width is still content + 2 × 32 px).
8. **Thumbnails**: an exact-area export draws frames without their names; the renderer draws their outlines over the export. The schematic draws images as grey tiles until 3g lands `files.urlOf` (tldraw drew previews). The leave drawing reads a snapshot of the scene (element rectangles, no rotation or frame clip), because the board page tears its canvas down in the same commit that unmounts the features.
9. **`export.copy` does not read the export policy** (the canvas has no policy store): every caller checks it (the dialog, the commands), and the api refuses originals whatever the client does.
10. **The Share dialog** is shared with the tldraw page and keeps that page's store for its own section; an owner's change reaches the Excalidraw page's store through the board event (as it reaches other tabs).
11. **Hide note authors** needs nothing in exports: notes on the new canvas draw no author name, and exports never include overlays.
12. **Vote badges** in exports come from `voteResultsForExport(ctx.canvas)`: 3f's ported workshops must call `provideVoteResultsForExport(ctx.canvas, …)`. Result `shapeId`s are api refs (`shape:<id>`), mapped with canvas-schema `fromShapeRef`.
13. **CSV tags** are read from `customData.lobby['tag:<key>']` with the board's `tagDef:<key>` names (3d's ported model is not there yet); the output rules (sorted names, "; ", text cells) are the tldraw page's.
14. **Ids** are element ids (no `shape:` prefix) in CSV rows and slide ids.
15. **pdf-lib** is loaded on the first PDF export on the Excalidraw page (plan §2.2); the tldraw page still loads it with the feature.

## Change requests

- **CR 3E-1 (applied as a `CR:` commit, contracts file `canvas/api/lobby-canvas.ts`)**: `ExportOptions.files?: 'original' | 'display' | 'canvas'`, which bytes an uploaded image is drawn from. Additive and optional.
- **CR 3E-2 (proposed, contracts)**: `LOBBY_CANVAS_MEMBERS` still says `stub` for `export.*`. The part is real when the board engine is attached before `createLobbyCanvas` (the board page does) and a stub naming 3e on a bare port, so the contracts test passes unchanged; a status such as `part` would make the §2.2 table say so.
- **CR 3E-3 (proposed, contracts)**: `registries.cursorVisible` is a single provider, but §3 lists two contributors (3e present, 3f hide cursors); the last `provide` wins. Present-export's provider also honours `lb_doc.workshop.hideCursors`, so 3f need not provide one; a composing provider (every contributor must say yes) would remove the coupling.

## Measurement: SVG export of the heavy board's largest frame (plan §2.10.4)

`e2e/excalidraw/present-export-heavy.spec.ts` (opt-in, `LOBBY_MEASURE_EXPORT=1`), one run on this workstation
with other agents' runs sharing the machine. The perf seed's heavy board (`HEAVY`: 20 frames, 4,500 notes,
200 images; 9,220 elements pushed in 19 pushes). The largest frame by elements, `f0`: 460 elements (230
notes with their labels), 3,904 × 3,480 scene px, no images inside it (the seed's images sit outside the
frames).

| Export of that frame | Size | Time |
|---|---|---|
| SVG (previews; Lobby's `@font-face`, `skipInliningFonts`) | 378,561 bytes, 1 embedded woff2 face (16,476 bytes) | 40 ms |
| SVG (originals) | 378,561 bytes (no images in the frame) | 30 ms |
| PNG 2× (originals) | 5,605,484 bytes | 263 ms |
| bitmap 3× (a PDF page) | 11,712 × 10,440 px | 68 ms |

Whole-file font embedding cost 16 KB here (one Latin face of Nunito); CJK or mixed-script text adds one
file per covering subset.
