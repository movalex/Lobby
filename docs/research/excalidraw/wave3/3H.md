## 1. What was built

### 1.1 History (`features/history/ported/`)

- **The dock panel** (`HistoryPanel.tsx`, feature id `history`, panel `history`, hidden for name-only
  guests as before). Same copy, test ids and rules as the tldraw panel: save a named checkpoint, the list
  (manual rows and the "Automatic" disclosure, the shared `CheckpointList.tsx`), live refresh on the
  `history.*` events and every resync, preview, restore as a new private board, owners delete (confirmed),
  duplicate (with "keep sharing" for owners), the `.json` export, and "Recently deleted" (editors with an
  account only, never fetched for anyone else). The shared pure modules (`api.ts`, `model.ts`,
  `checkpoints-model.ts`, `CheckpointList.tsx`) are reused unchanged.
- **Live "Recently deleted"**: `canvas.on('change')` replaces tldraw's store diff (`ported/model.ts`
  `touchesDeletedElements`): any delete (remote ones included), or a listed element coming back (an undo,
  another tab's restore, reported as `created`), refreshes the list 700 ms later.
- **Restore**: through the api as before. What came back is selected by element id and brought into view
  with `canvas.viewport.zoomTo(bounds, {maxZoom: min(1, zoom)})` (3b's member).
- **The preview** (`CheckpointPreview.tsx` + `canvas/preview/index.ts`): the same modal dialog, header,
  counts and buttons. The checkpoint's elements (`CheckpointContent.elements`, v2 bodies) are drawn by spike
  A11's `CheckpointPreview` (exportToCanvas bitmaps, an overview and a detail pass, Lobby's own drag to pan
  and Ctrl/pinch-wheel to zoom), never a second `<Excalidraw>`. Images load with Lobby's `ImageLoader` and
  the board's `FileUrlResolver` into a preview-only files map (the board's own file access; never
  `addFiles` on the live board, never stored). It opens on the first frame in presentation order when the
  whole checkpoint is unreadable at the fit zoom (DANA2-05, `prefersFirstFrame`), never above 100%.
  `data-shape-count` counts objects as people see them (a note and its label are one).
- **Export policy**: `export-allowed.ts` asks `GET /api/boards/:bid/export-policy` on open, applies every
  `export-control.policy` event and refetches after each resync (the tldraw panel reads sharing's
  tldraw-signals store, which the Excalidraw page does not fill). Unknown means allowed; the api refuses
  anyway.

### 1.2 AI (`features/ai/ported/`)

- **State** (`runtime.ts`): the same four per-canvas values (status, menu, job, summary panel) on
  `lib/signals.ts` atoms.
- **Target** (`target.ts`): the selection (a selected label stands for its container), else the frame
  under the point (context menu) or in the middle of the view. Counts use the api's own facts
  (`apps/api/src/features/ai/sources.ts`): a note's text is its label, frames stand for their children,
  prompt markers (`customData.lobby.prompt`), revealed private notes (`lobbyServer.privateNote`), AI notes
  (`customData.lobby.ai`) and who last typed a label (`lobbyServer.lastEditedBy.uid`) feed
  `splitThemeNotes`. Existing groups (DANA-10) are labelled rectangles and ellipses in the frame that are
  not AI's, a slot or a swatch. Refs sent to the api are `shape:<elementId>`.
- **Actions** (`actions.ts`): the same flow and copy: status from `GET …/ai` (latest answer wins), the
  notice, one job at a time with Cancel, waiting for this tab's edits to be saved (the engine's save
  status) before the request, the api's own error messages, the board and workspace switches.
- **Apply** (`apply.ts`): every result is one `canvas.transact`. Every element made carries
  `customData.lobby.ai = {by: <me>}` (create-only, the server checks `by`) and
  `customData.lobby.kind = ai-theme-label | ai-summary | ai-heading | ai-idea | ai-action-item`. The
  layout is the tldraw page's (`../layout.ts`, unchanged), computed in the frame's space (scene
  coordinates less the frame's origin). Themes: notes move with their bound labels; labels are text
  measured before the write with `canvas.text.measure` and wrapped at the cluster width, so one pass places
  them; clusters go under a map beside the notes (DANA-10) when the frame may grow downward; the frame grows
  only when needed; nothing stays selected. Summary: a rectangle (the light-violet tint) with its words as
  its bound label, "Summary" first. Ideas and action items: a heading and a grid of notes as large as the
  first note of the target, beside the selection in its frame, else at the end of the frame (DANA-07); the
  notes join the frame in a derived write of the same undo step (`joinPrevious`, see CR-3H-3).
- **The Undo toast** (DANA-09): after a result, any change of this tab that is not the result's own change
  batch (a local edit, an undo or redo) takes the toast away; remote edits do not. The result's own batch is
  recognised by the versions it wrote.
- **Entry points** (`menus.tsx`): a `SelectionBarItemSpec` (the "AI" button, `selection-ai`), a
  `contextMenu` submenu in the `ai` group (Summarize, Group into themes, Action items, Generate ideas…;
  read-only people get Summarize only) and two `mainMenu` checkbox entries in the `board` group ("AI on this
  board", "AI on by default in this workspace"), all for 3a's shells to render. Until the page has a
  `selectionBar` host slot, a small stand-in bar over the selection (`ai-entry-fallback`, a screen overlay)
  carries the same button; it renders nothing once 3a's shell is there.
- **The overlay** (`Overlay.tsx`, a `screen` layer that takes no clicks itself): the popover (menu, ideas
  form, notice, regroup question), the busy pill and the summary panel, with the tldraw page's keyboard and
  focus rules (A11Y-08, A11Y-15, A11Y2-03).

## 3. Deviations from the tldraw features

- **The preview is a bitmap.** Its words are also listed in a visually hidden list inside the canvas area
  (`checkpoint-preview-text`), since a bitmap cannot be read aloud or searched. There is one page, so the
  page picker is gone. A v1 (tldraw) checkpoint body says "This checkpoint was saved before the canvas
  update and can't be previewed here yet. Restoring it as a new board still works." until the api converts
  v1 bodies on read (the `apps/api` → `tldraw-import` edge, W1-9).
- **Keyboard after the preview (DANA-01).** Focus goes back to the button that opened it; the board takes
  the keyboard on the next click. tldraw's "editor stays blurred" defect cannot happen (Excalidraw's keys
  follow DOM focus). The spec checks Delete, Ctrl+Z and N after closing.
- **Restore's camera** uses 3b's `viewport.zoomTo`, a stub on this branch: what came back is selected and a
  console warning says it could not be brought into view.
- **AI results are plain text** (no rich text on the new canvas): theme labels and headings are not bold;
  the summary card is a labelled rectangle whose first line is "Summary". Notes keep their square size
  (their words shrink to fit); they no longer grow with long text.
- **Regrouping** recognises an earlier run's theme label by where it sits (an AI theme label directly above
  notes that move now, with no staying note there), since `customData.lobby.ai` has no room for the list of
  notes it labelled (the tldraw `meta.drAi.notes`). Grouping the same notes twice gives the same result (the
  unit and e2e tests check it).
- **Entry points on this branch**: until 3a's shells are on the page, the AI button sits on the stand-in bar;
  the context-menu steps of the specs select the frame instead (the same target) and the board switch is
  the api call the menu makes. The specs take the real menus as soon as the slots have providers.
- **Fonts and sizes** of what AI writes: Nunito (Lobby's note font on the new canvas), 24 px for labels and
  headings, 18 px for the summary.

## 4. Findings for other owners

- **3a (canvas UX):** Excalidraw's own Delete on a frame keeps the frame's children (`actionDeleteSelected`
  selects them instead), while Lobby on tldraw deletes the frame with what is in it. "Recently deleted" then
  lists the frame alone ("Frame", nothing inside). The ported specs delete a frame with its contents in one
  step through the canvas, as Lobby's delete should.
- **3e (sharing):** the History panel reads the export policy itself until a ported (signals) export-policy
  store exists; replace `history/ported/export-allowed.ts` with it then.
- **2C (change stream):** right after a redo that touched the same elements, a write's own change batch was
  once reported with source `history` instead of `local` (1 run in 3, not traced further; a guess: the ids an
  undo or redo marks keep their mark until they are next scanned). The AI toast now compares versions for every non-remote batch;
  other features that treat `history` as "the user pressed undo" may see the same.
- **2E/e2e:** the default suite's fake OpenAI sits on `E2E_PORT_BASE + 3`, outside a run's own range; the
  ported AI spec uses `base + 10`.

## 7. Wave 5: the early review's findings (W5-04, W5-47)

Branch `engine/w5f-3h` from `engine/excalidraw` f336ae4 (`docs/research/excalidraw/REVIEW-W5-EARLY.md`).
Only 3h's files changed: `features/ai/ported/**`, the shared pure `features/ai/layout.ts` (one new
function the tldraw page does not call) and `e2e/excalidraw/ai-actions.spec.ts`. No change request, no
lockfile, workspace or catalog change; the tldraw page is unchanged.

**W5-04 (major, P1): "Group into themes" pulled ideas out of the frame.** A note made with N inside a frame
has no `frameId` until W5-01 lands (2C). With one among the ideas, the notes no longer shared a frame, so
the clusters went to the page: the regroup question was skipped, the clusters landed below the frame, the
frame's notes lost their frame, the frame did not grow and the camera did not follow; Present and the PDF
then showed the Brainstorm frame without its ideas (DEMO 1:20 → 2:45 → 3:30).

- `target.ts`: `frameOfElement` is an element's own frame, or for a loose element the innermost unlocked
  frame holding its centre (the frame N joins it to once W5-01 lands). `homeFrameOf` is the place most of
  the elements are in, a tie going to the frame under their centre. The regroup question
  (`existingGroups`) uses it, and a frame target names the loose elements lying in it beside the frame, so
  they are counted, sent and grouped. Both read the elements' own fields: the port's `bounds` scans the
  scene per call (CR 3b-7) and these run over every loose element, in the context menu's predicates too.
- `apply.ts`: themes are planned per space (`planThemes`) and written in one `transact`. Loose notes and
  notes on the open canvas join the home frame; a note of another frame is grouped in its own frame, so no
  note leaves its frame. In a frame's space the loose elements lying in it are obstacles; the clusters start
  inside its margins; a frame that grew (or whose clusters went under its map) is brought into view.
  Summarize, Action items and Generate ideas use the same home frame.
- `layout.ts` `alignRows`: packing puts each cluster at the highest free spot, so an obstacle hanging into
  the row held one cluster lower (the facilitator's "36 units off one line"). Clusters side by side whose
  tops are within 64 move down to the row's lowest top, all of the row or none, only when nothing is in the
  way and never further past a frame's floor. Only the ported page calls it.

**W5-47 (minor, the AI half): the summary gave the keyboard to the canvas.** The popover forgot its opener
when it closed as a request started (the board takes the focus first, the popover's focus-leave handler
then cleared it), so Escape or × on the summary panel focused the canvas. A request now takes the opener
along (`AiJob.opener`, `AiPanelState.opener`); closing the summary from the keyboard gives the keyboard
back to the AI button, and to the board when it was asked for from a menu. Present mode's half is 3e's.
