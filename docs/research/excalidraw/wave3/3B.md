## 2. How the tldraw code maps

| tldraw | New canvas |
|---|---|
| `editor.zoomToBounds({targetZoom, inset})` | `viewport.zoomTo(bounds, {maxZoom, zoom, inset})`. `inset` is per side (tldraw's is the total, 128 by default = 64 per side). |
| `zoomToFit` / `zoomToSelection` / `resetZoom` / `zoomIn` / `zoomOut` | `zoom.ts` over the part, with the same rules (a fit may zoom in to the top step; the selection rule at 100%). |
| `getCameraOptions().zoomSteps`, `getBaseZoom` | `viewport.limits()` |
| `createDeepLink`, `navigateToDeepLink`, `parseDeepLinkString` | `lib/deep-link.ts`, `start-view.ts` `navigateToDeepLink` |
| `meta.presentationIndex` / `presentationSkip` | `customData.lobby.present.index` / `.skip` (strict `{index?, skip?}`; `null` removes the key) |
| document `meta.drStartView` (with `pageId`) | `lb_doc.startView` (no page) |
| camera key `draftroom:camera:v1` (tldraw camera) | `draftroom:camera:v2` (`{x, y, zoom}`: the scene's top-left). v1 is still read. |
| `registerExternalContentHandler('text')` | `contentHandlers` (`navigation.bulk-paste`, priority 50) |
| `createShapes` + `reparentShapes` | `tx.create('note')` then `tx.setFrame` in a second write with `joinPrevious` (one undo step; §3 D6) |
| `instantiateTemplate` records + `createShapes` / `createBindings` | `instantiateSceneTemplate` elements + `LobbyTx.insert` (CR-2D-2) |

## 3. Deviations from today's behaviour

Each deviation is also in the workflow result.

1. **D1. Only owners can set or clear the board's start view on the new canvas.** canvas-schema `doc.ts` makes `startView` an owner key (`writer: 'owner'`), so the room refuses an editor's write (`docDenied`). The tldraw board let editors set it too. The entries are shown to owners only. For parity, see request CR 3b-3.
2. **D2. A locked frame keeps its place in the order and its skip mark.** The room refuses `customData` writes on a locked element (`LOCKED`, room/merge.ts step 5). A reorder writes only the unlocked frames, so a locked frame keeps its old index. Its row has no drag handle, arrows or skip button. The tldraw board reordered locked frames with `ignoreShapeLock`. See request CR 3b-4.
3. **D3. Pasted notes use the new-note face** (Lobby's sans, the default note fill) rather than the pasted-note face 2D prepared (`noteElementsFromText`: Excalifont, 22 px, Lobby's palette colour). `tx.create('note')` rebuilds a note (CR-2D-2). The layout, the grid, the cap and the placement are the tldraw board's.
4. **D4. "Paste as text" makes one text element** at the paste point, written by Lobby. On the tldraw board the original content went back to tldraw's default text handler.
5. **D5. A template from the dashboard (`?template=`) is an undo step on the new canvas.** `LobbyCanvas` has no write that stays out of the history. On the tldraw board it was `history: 'ignore'`. It is blocked anyway until CR-2D-2.
6. **D6. The first view waits for the board to settle:** no change for 150 ms, at most 2.5 s after the feature mounts. Features mount after the first `welcome`, but a fresh session's welcome can carry the room's cached reset snapshot (up to 5 s old) with a `changes` catch-up right behind it (§4 F2). The first view therefore comes about 150 ms later than on the tldraw board.
7. **D7. Legacy page links (`?d=p<page>`) open on the whole board** at no more than 100%. The converter flattens pages side by side and keeps only their offsets, not their extents. tldraw showed that page's content. Lobby never wrote page links: copy link and search wrote shape links.
8. **D8. Board search has no tag filter and no `#tag` search yet.** They are the tags feature's (3d, `features/tags`), and the ported panel has no extension point for them. The placeholder no longer says "#tags".
9. **D9. The minimap is Lobby's own** (§4.2): boxes of every item plus the view. It is not tldraw's rendered minimap. Its test ids are the same.
10. **D10. Zoom steps top out at 8** (tldraw's), while Excalidraw's own wheel zooms to 30. From above 8, a zoom-out step lands on 4, as tldraw's rule does.
11. **D11. On the new canvas the dashboard's hits are `?el=` links.** The legacy `?d=` still opens on the new board page, and the default build's dashboard still writes `?d=`.

## 4. Change requests and findings

**Applied (a `CR:` commit, 0780539):**
- **CR 3b-1** changes three frozen files:
  - `canvas/api/impl.ts` `LOBBY_CANVAS_MEMBERS`: `COMPOSED_BY_PARTS` lists a wave-3 owner's landed part members that are composed from the canvas's own members. Their status is `composed`, not `stub`.
  - `canvas/api/contracts.test.ts`: the stub test checks every member still `stub` in the table, not 3b's `zoomTo` by name, and checks that a landed composed part is real on a bare port.
  - EXCALIDRAW-CONTRACTS.md §2.2: the regenerated rows and counts (22 composed, 12 stubs).
  - No member, owner or signature changed. Other wave-3 owners whose parts compose can add their paths to the same set. §12 is left to the integrator.

**Requested (not applied):**
- **CR 3b-2** (contracts `lobby-canvas.ts` + 2C `canvas/board/input.ts`): `CanvasInputEvent` `wheel` and `pinch` carry `deltaX`, `deltaY` and `deltaMode`. With them, 3b's feature can take wheel and pinch zoom below 0.1 (§4.2 "Lobby's capture wheel listener", its floor being the whole-board fit). Excalidraw's own wheel snaps to 0.1 today. Not built: see §6.
- **CR 3b-3** (canvas-schema `doc.ts`, spike B's C0): `startView` writer `editor`, for parity with the tldraw board (D1). This is a product decision for the owner.
- **CR 3b-4** (O1, room): let `customData.lobby.present` be written on a locked frame, since it is board metadata like the tldraw board's `ignoreShapeLock` (D2).
- **CR-2D-2** (contracts + 2C, already open): `LobbyTx.insert(elements)`. The template insert calls it (`template-insert.ts` `insertElements`, which throws `NotImplementedError('contracts', 'tx.insert (CR-2D-2)')` until it exists). Paste as notes would use it too (D3).

**Defects found in other owners' code** (each is designed around here; none is fixed here):
- **F1 (spike B / 2C, `canvas/port-impl.ts` `transact`): an update to an element created in the same `transact` is dropped.** The step's scene is built as `[...order.map(current.get), ...created]`, and `created` holds the objects from before the update. For example, `tx.create('note')` then `tx.setFrame([id], frame)` in one step left the note outside the frame (seen in RETRO-01's first run). 2C's `tx.duplicate` writes `groupIds` and `frameId` onto copied notes the same way, so those writes are lost too. The paste works around it with a second write under `joinPrevious`.
- **F2 (O1 / O2): a first visit within 5 s of a board-document write gets the old `lb_doc`.** `element-room.ts` `snapshotFor` caches the reset snapshot (with its doc) for 5 s. The client's `onSnapshot` then replaces the fresh `welcome.doc` with the snapshot's doc. The `changes` catch-up after a cached snapshot carries elements but no doc. Seen with PRE-08: a start view set 2 s earlier was not seen by bob. It is pinned by a `test.fail` spec (`navigation-start-view.spec.ts`, the last test).
- **F3 (2C, contract): features mount after the first `welcome`, which does not mean the board's content is in** (the same cached snapshot plus `changes`). A "caught up" signal (for example `LobbyCanvas.on('loaded')`, or the welcome emitted after the catch-up) would let features stop guessing (D6).
- **F4 (2C): a camera set through `viewport.set` is not read back at once.** Excalidraw applies it on its next render, so `viewport.get()` right after `set()` returns the old camera. The first view checks the rectangle it moved to instead.
- **F5 (2C, the camera tween): an animated move can end a hair off its target** (for example 0.10000000000000002 for 0.1). The zoom menu rounds for display.

**Coordination with other owners:**

## 6. Not ported, and why

- **The wheel and pinch below 0.1** (plan row 3b "+0.5"): it needs CR 3b-2. The keys, the zoom menu, fit, the frames panel, links and the first view all go below 0.1 already.
- **The level-of-detail pass for zoomed-out views** (plan row 3b "+3", §8.5): it is a render pass inside the engine's overrides (`canvas/overrides.ts`, spike-owned) and is not started.
- **The UI clicks on the context menu, board menu, selection bar and shortcuts dialog:** these are 3a's shells. The specs run the same entries through the page's registry, and a click spec belongs with those shells at integration.
- **Search by tag** (D8, 3d) and **Present following the frame order** (3e).
- **F15 image file-name search e2e:** it needs 3g's upload path. It is unit-tested.
- **The tldraw tests of other features that share these spec files** (the toolbar pin, type-to-edit, palette, lock, alignment, Hide note authors, F3, F8, RETRO-09/14/20/21) belong to their owners.
