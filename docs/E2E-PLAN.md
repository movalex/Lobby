# Feature e2e plan (from the features integration pass, 2026-09-27)

Consolidated browser scenarios per feature; **P0** marks must-cover flows. Test ids are the contract in docs/FEATURES-M2-CONTRACTS.md.

- [P0][integration] Event stream + reconnect: open a board as A and B. SIGKILL and restart the API (stack.api.restart()). Afterwards an event-driven change (e.g. B posts a comment) still appears on A without a reload (onResync refetch plus a new stream). Exactly one /api/boards/<id>/events request is pending per page (page.on('request') count).
- [P0][integration] Presentation is clean: with an open comment thread and a canvas-ux selection, click present-button. No visible [data-testid=comment-pin], no .dr-cux-selbar and no .dr-topbar. After Escape the pins come back. (The user's own vote-dots and revealed vote-count badges stay by design; timer-floating shows if a timer runs.)
- [P0][canvas-ux] Toolbar layout pin (COL-07/PRF-09): at 1440×900 the visible toolbar test ids are, in order: tools.select, tools.hand, tools.note, tools.text, tools.rectangle, tools.draw, tools.arrow, tools.frame, tools.asset, tools.comment, tools.dr-templates, one overflow slot, tools.more-button. Add a visual snapshot of .tlui-main-toolbar. A viewer has no tools.dr-templates.
- [P0][canvas-ux] Miro keys (MAK-05/06/07/10/11): l → editor.getCurrentToolId()==='arrow'; p → 'draw'. PageUp, PageDown, Shift+PageUp and Shift+PageDown change the z-order (getSortedChildIdsForParent). Control+Shift+L locks and keeps the selection, Delete does nothing, and Control+Shift+L again unlocks; bare Shift+L does nothing. Control+0 gives getZoomLevel()===1 and devicePixelRatio===1. Alt+1 fits all, Alt+2 fits the selection, m toggles [data-testid="minimap.canvas"]. Control+Alt+/ opens the dialog, which lists 'Comment C', 'Show or hide comments', 'Present Ctrl+Alt+Enter' and 'Export as PDF'.
- [P0][canvas-ux] Two-browser lock (MAK-05): A presses Ctrl+Shift+L on a note. B sees isLocked within 2 s, and B's drag does not move it.
- [P0][canvas-ux] Type-to-edit (COL-04): A selects one note and quickly types 'Hello'; the note text ends with 'Hello'. With a geo shape selected, 't' selects the text tool. With nothing selected, 'c' selects the comment tool. A viewer typing on a selected note does not edit it.
- [P0][canvas-ux] Bulk paste (COL-05): grant clipboard permissions and write text/html plus text/plain (TSV 3×3 with one empty cell). Ctrl+V shows bulk-paste-prompt with bulk-paste-notes focused. bulk-paste-notes gives 8 selected notes in the source rows/columns; one Ctrl+Z removes them all; B sees them. bulk-paste-text gives one text shape. A single line or a URL shows no prompt. 620 lines give 500 notes and bulk-paste-notice with '120 more cells were left out'.
- [P0][canvas-ux] Note palette (COL-06): select 2 notes. note-palette shows 13 note-color; [data-color=blue] recolours both; one Ctrl+Z restores both.
- [P0][canvas-ux] Templates in board (PRE-02/03): tools.dr-templates opens template-picker. Clicking template-option[data-template-id=storyboard] leaves the shapes selected, inside getViewportPageBounds, not overlapping existing content. A bound arrow stays attached when its target is dragged. One Ctrl+Z removes everything. Inserting twice gives unique ids.
- [P0][canvas-ux] Frame outline (MAK-13): dock-tab-frames shows frame-outline with frame-row[data-frame-id] in presentation order. Clicking a row selects the frame and brings it into view. Dragging the last row onto the first gives every frame a numeric meta.presentationIndex, and B's panel shows the new order within 2 s. Ctrl+Z restores it. frames-auto-order restores the layout order (one undo). frame-skip sets meta.presentationSkip===true and present skips that frame. A viewer has no reorder or skip controls.
- [P0][canvas-ux] Board search (MAK-12): Ctrl+F, also while editing a note, opens dock-panel-search with search-input focused. search-result[data-shape-id] lists matches; search-highlights data-match-count equals the result count. Enter selects and zooms to the result, and Enter again goes to the next. search-filter[data-filter=frames] narrows the list. Escape closes the panel and removes search-highlights.
- [P0][canvas-ux] Copy link (PRS-04): copy-link-selection puts /b/<id>?d=s<shapeId> on the clipboard. B opens it and lands with the shape selected and in view, with ?d removed. frame-copy-link does the same for a frame. A signed-in user without access gets no-access.
- [P0][canvas-ux] Start view (PRE-06): A reloads and gets the same camera (±1 px). A camera far from content falls back to fit on reload. B's first visit shows getCurrentPageBounds with zoom ≤ 1.
- [P0][canvas-ux] Alignment guides (MAK-02): on a fresh profile editor.user.getIsSnapMode()===true, and an explicit off survives reload. Selection bar (MAK-03): 2 shapes show align-* without distribute; 3 shapes show distribute-*; align-left is one undo.
- [P0][canvas-ux] Heavy board (PRF-02): seed 4,500 shapes, then paste 500 lines as notes; 5,000 shapes exist.
- [P0][comments] Commenter on a read-only canvas: grant commenter and press C (getCurrentToolId()==='comment'). Click a note, type into comment-composer and press Enter. thread-popover[data-thread-id] has one comment-item, and the owner sees comment-pin[data-thread-id] appear live.
- [P0][comments] Pin follows its shape: after the owner moves the note and zooms (setCamera z=1.7), the pin's bottom-left equals pageToViewport(bounds.x+u*w, bounds.y+v*h) within 2 px on both clients.
- [P0][comments] Mention (REV-03/05): type '@Oli', click mention-option[data-user-id], press Enter. - [P0][comments] Mention without access: '@zzz' shows mention-no-match; 'Invite with Share' opens share-dialog. A forged token '@[X](usr_…)' posted via the API renders as plain '@X' (no .dr-cmention).
- [P0][comments] Resolve/reopen (REV-02/04): thread-resolve removes the pin for everyone live. In comments-panel, comments-filter=resolved lists comment-row[data-state=resolved]; clicking it opens the thread and thread-reopen brings the pin back.
- [P0][comments] Edit/delete: comment-edit shows only on the author's own items, and '(edited)' appears live elsewhere. A commenter has no comment-delete on others' comments. The owner's comment-delete then comment-delete-confirm removes someone else's reply live.
- [P0][comments] Draft survival: a reply draft survives 'Close thread'. In the comment tool, a new-comment draft survives Escape (new-comment-popover gone, tool still 'comment') and a reload.
- [P0][comments] Shift+C per user: the owner has 0 comment-pin while another user still has them; still 0 after reload; Shift+C shows them again. comments-hide-pins reflects the state.
- [P0][comments] Orphan (REV-06): deleting the anchored note removes the pin, and comment-row[data-orphan=true] says 'On a deleted object'. Ctrl+Z brings the pin back with data-orphan=false.
- [P0][comments] Viewer: C shows comments-readonly-notice and the tool stays select. The viewer can open a thread-popover but has no comment-composer. POST /api/boards/:bid/threads returns 403.
- [P0][comments] Hover preview and deep link: hovering a comment-pin shows comment-preview. /b/<bid>?thread=<id> opens thread-popover and removes the param. An unknown id shows comments-gone.
- [P0][comments] Notifications across boards: a mention on board A shows in the bell on board B as a notification-item 'on <A>'. Clicking it navigates to /b/A?thread=… and opens the thread. notifications-mark-all clears notifications-count.
