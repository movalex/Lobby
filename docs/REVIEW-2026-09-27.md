# Miro-user persona review and fixes — 2026-09-27

Four reviewers used Draftroom the way a Miro user would, each with the real stack (api + sync + worker from `e2e/tests/support/stack.ts`, a production web build behind `vite preview`) and headless branded Chrome driven by real mouse, keyboard, touch and drag-drop input:

- **Maya** runs a 30-minute agency retro: 4 participants, 1 viewer, and a client on a review link.
- **Jonah** is a creative director building a mood board and a storyboard: 48+ uploads, arranging, locking, presenting, exporting, with an editor and a client commenter.
- **Priya** is a client reviewing asynchronously on a commenter review link, on desktop, a 390×844 phone and a 768×1024 tablet.
- **Performance** checked every §13 gate and PRF-01..05, with seeded boards of 2,050, 5,200 and 2,040 shapes.

A triage pass turned the 78 findings into four fix batches: media and assets, canvas UX, facilitation and review, and shell, sharing and platform. It deferred the rest with a reason, and an integration pass closed the work.

All four reviews ran over loopback (0 ms network RTT), on one workstation:
- Ryzen Threadripper 9970X, 256 GB RAM, RTX 5090, Windows 11, Node 24.19.0;
- Chrome with the hardware GPU;
- other agents' browsers running at the same time.

There is no agreed laptop or network yet (build plan §13), so every "pass" below is a pass **on this machine**. The personas were not re-run after the fixes. The "after" column holds only numbers someone actually re-measured, and says who measured them.

### 2.1 Integration re-measurement

After both e2e runs, integration re-ran the performance persona's harness on the final tree. Method:
- A copy of the harness, in `scratchpad/personas/integration/perf/`.
- A fresh production build (`VITE_DRAFTROOM_DEV_AUTH=1`) and the real api + sync + worker (`startStack`), on the default e2e ports.
- The same generated boards and images (`seed.mjs`: typical, heavy, and a separate typical-sized board for the concurrency run, set to `workspace_edit` as before).
- Branded headless Chrome with the hardware GPU, 1536×864 at DPR 1.25.
- Cold opens verified as cold: the sync room reopened for every run (13 room opens = 3 imports + 10 benchmark opens; `IDLE_EVICT_MS` 5 s).
- Whole-machine CPU was 6–7% busy during the opens and 14% during the 10-minute load, against 7–10% and 12–16% at review.

| Measure | Review (before fixes) | Integration (final code) |
|---|---|---|
| Typical board, cold open to first handled click (median of 5) | 1.91 s (1.89–2.11) | 1.82 s (1.81–2.09) |
| Heavy board, cold open (median of 5) | 3.51 s (3.44–3.69) | 3.36 s (3.27–3.49) |
| Heavy board pan fps at fit, default UI | 9.6–15.6 (minimap open) | 26–32 (minimap closed) |
| Heavy board zoom fps at fit, default UI | 7–8 | 49–53 |
| Heavy board pan fps at 0.25 / 0.5 / 1, default UI | 41–44 / 45–49 / 46–53 | 49–54 / 58–60 / 59–60 |
| 20 sessions × 10 min: remote change visible in a Chrome tab, p95 | 327 ms | 283 ms |
| … a tab zoomed to one frame, p95 | 278 / 288 ms | 209 / 216 ms |
| … a tab on the whole-board overview, p95 | 345 / 356 ms | 309 / 318 ms |
| 20 sessions × 10 min: acknowledged edits missing, convergence | 0 real misses (7 harness id reuses), converged | 0 of 866, converged |

The frame-rate and latency gains line up with the lower per-frame cost in the tab (the minimap is closed by default, and the camera timeout is longer). The two were not separated by an A/B test, and machine load was similar but not identical. Not re-measured by integration:
- the mood board;
- CPU-throttled opens;
- the 30-minute and 30-editor runs;
- the restart/kill runs;
- the join storm.

## 4. Top remaining gaps for a Miro user (priority order)

1. **Clients and guests without an account (RETRO-04b).** Miro visitors join a workshop or a review with a name, not a sign-up. Both Maya's client and Priya hit this. It needs a new identity model and a security review.
2. **Anonymous and private brainstorming (FAC-07, RETRO-03b).** "Hide note authors" is only a mitigation: author data still syncs and note text is visible as it is typed. For retros this is psychological safety, and it was Maya's first requirement.
3. **Hearing about feedback outside the app (RETRO-18, PRI-05b).** There are no email or digest notifications for mentions, replies and action owners. The dashboard bell only helps people who open Draftroom. It needs an email-provider decision.
4. **Live edit latency and big-board frame rate.** Browser edit visibility still misses the 250 ms p95 gate: 283 ms overall and 309–318 ms on a whole-board view, even on loopback (PERF-02). Heavy boards pan at 26–32 fps at fit (PERF-03b). Opening is CPU-bound, so an ordinary laptop may miss the 3 s open gate (PERF-06). The first two are inside tldraw; all three need an agreed laptop and network target and a real WAN measurement.
5. **Arranging media quickly.** The mood-board workflow still lacks "arrange as grid / tidy up" and "select only images" (MAK-18, MAK-17: Jonah's #4). It also lacks a PDF page viewer or "extract pages" (F7b), animated GIFs (F9) and deep-zoom derivatives (F10).
6. **Facilitation extras.** Missing: reactions, +1 and raise hand (FAC-08); a presenter session with a clean follower view (PRS-07); votes on a selection or several frames (RETRO-10); and a PDF with vote results and a comments/actions appendix (RETRO-05b).
7. **Phone and tablet beyond the top bar.**
   - Cold open on 4G is 4.6 s to shapes (PRI-15).
   - OS dark mode is ignored.
   - iPad Safari and phone frame rates are unmeasured (PRF-03, PRF-10).
   - Firefox and Safari are untested in general.
8. **Owner controls.** Missing: guest export and download permission (PRS-12), an owner-set start view (PRE-08) and board thumbnails (DSH-05).

The deploy prerequisites are unchanged: Clerk keys, a tldraw license key for the host, and a verified Render deployment.

Integration fixed, at the root:

- **Docs:** this file, the persona-fix subsection in `docs/FEATURES-M2-CONTRACTS.md` §3, and `docs/PROGRESS.md`.

Accepted deviations and known limits, from the fix reports and checked here:
- **The "touched" route is a GET.** The sync server reports canvas writes with `GET /internal/boards/:bid/touched?at=`. A GET, because the api's root CSRF hook refuses POSTs without the web Origin. It requires the internal secret, is not proxied by the web server, and only moves `updated_at` forward. It was left as is: exempting `/internal` from the CSRF hook would weaken the hook for every future internal route.
- **Loading tiles everywhere.** `assets/pending-image.css` styles every empty `.tl-image-container` as a loading tile, so an image whose src never resolves (a foreign URL) shows a grey tile instead of nothing.
- **Drop and upload rules:**
  - Ctrl+U never fills a template slot; only a real drop or paste point does.
  - A far-away grid is reached by panning at the current zoom.
  - File cards keep a fixed page size.
  - The metadata cap is 6 requests in flight.
  - A large image still processing after 60 s shows "Preview on its way" until the next resolve.
- **Keyboard order for comments.** Keyboard commenting on a note is C → Tab → Enter. "Tab to a note, then C" types "c" into the note (COL-04 type-to-edit). That is a product decision, not a bug.
- **Session-only font.** The sans default and an explicit font choice last for the session only: tldraw does not persist next-shape styles.
- **Join queue ceiling.** Beyond about 150 simultaneous joins on a 6k-record board, the last clients hit tldraw's 10 s connect wait and reconnect once (PERF-05).
- **Minor UI leftovers:**
  - The presence avatar is still a "Stop following <name>" toggle while following.
  - On phones, a new comment's ghost pin can sit under the bottom sheet.
  - The Timer popover scrolls on short screens.
  - The vote stepper overlaps the selection bar under a selected note (pre-existing).
  - The role-change toast does not say who made the change.
- **Measurement harness.** The performance persona's `fps-bench2.mjs` pressed M to *close* the minimap, which now opens it. Integration's copy checks `[data-testid="minimap.canvas"]` first; the canvas-ux engineer's copy already handled the new default.
