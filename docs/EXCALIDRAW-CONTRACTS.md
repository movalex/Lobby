## 0b. Stale clients: the per-reader downgrade rule (CONTRACTS_REV 12 on; 2026-10-09)

A web build stays open in people's tabs for days after a deploy, and every client parses each server frame with its own build's strict `ServerMessage` and drops the WHOLE frame on one field or value it does not know (the web's socket transport since C0: no error shown, Saved still shown). Wave L's stale pair (c) found it: the deployed rev-11 web dropped every `changes` frame that carried a frame's `present.mins`, with every op committed with it. Every contracts revision from 12 on follows these rules (L-2 in §12).

1. **The room knows the reader's revision before its first frame.** A client names the contracts revision it reads in its connect URL, `/connect/:boardId?sessionId=…&rev=<CONTRACTS_REV>` (`protocol.ts` `CONNECT_REV_PARAM`; the web's `connectQuery`, `canvas/sync/transport/socket.ts`), to every room: an older room reads only `sessionId` and the ticket. A socket that names none is read as `UNANNOUNCED_REV` (11: every web before rev 12); one that sends presence `t` is a rev-12 reader from then on (the fallback). A revision learned from presence alone comes after the welcome and after a welcome's replayed pushes, so it cannot be the primary signal.
2. **One function, at one send point.** `frameForReader(reader, frame, stored)` (`protocol.ts`) gives every server message type in the form a reader of that revision parses, and returns the frame itself when nothing is to change. The room applies it at `Session.send` (`apps/sync/src/room/reader-frames.ts`, `element-room.ts`), the only code that writes to a session's outbound queue (`reader-frames.test.ts` scans for any other), and serializes each frame once per revision for every session it goes to. Two paths are pre-serialized for speed and are in their reader's form by construction: the catch-up frames (`c` ops of the stored rows: `opForReader` never changes a `c` op) and the presence hub's frames (built per reader form with `presenceForReader`, which is `frameForReader`'s presence rule).
3. **Downgrade without loss wherever the reader keeps the data.** A field added to a `customData.lobby` value after 11 is listed in `LOBBY_FIELD_ADDITIONS` with its revision (rev 12: `present.mins`). A `p` op whose `c` carries one goes to an older reader as the `c` op of the element as stored: every revision of the same `ELEMENT_SCHEMA_VERSION` takes a whole element's `customData.lobby` values as they are (only `LobbyPatch` checks values), so its copy stays the server's exactly (its convergence hash, its lost-push decisions and its undo all compare against that copy). A deleted element's patch keeps its form with the field left out (tombstones travel redacted, and only `TOMBSTONE_KEYS` are compared). A new presence field is left out by `presenceForReader`. A new element field is an `ELEMENT_SCHEMA_VERSION` bump, which the hello handles, not this rule. A new message type, field, enum value or code gets its own rule in `frameForReader` (left out, or mapped to what the older revision knows).
4. **An older writer cannot erase what it cannot know.** A push carries its socket's revision (`PreparedPush.writerRev`). Its write of a `customData.lobby` key keeps the stored fields added after its revision (`lobbyWriteOf`): a rev-11 `present` reorder or skip keeps `mins`, and its removal of `present` (Auto-order) keeps `{mins}` alone; a create over a tombstone too. It is merged in the same commit, and the ack's `fix` names the stored value (`c:<key>`), which the writer folds into its undo step like any server fix (its Ctrl+Z still undoes, and keeps the minutes). Per-op validation, the class and lock rules, leases, the arrow rules and the undo rules are unchanged; a writer of the current revision is taken as written (a rev-12 write without `mins` clears them). **The writer is the build that made the change, not the socket that carries it** (compat refix, round 1, L-3): a rev-11 page's offline queue (IndexedDB `lobby-offline`) is taken over after a reload, or by the next tab of the board, by the current web, whose socket names rev 12. So the web stamps what it queues with its revision (`OfflineEntry.rev`, `LostPushRecord.rev`; absent: `UNANNOUNCED_REV`, every queue 437b4e7 wrote), and its engine core completes a queued copy or lost record of an older page with `lobbyWriteOf` against the server copy before any of it is pushed or decided (`withOlderLobby`, in `settleDirty` and `replayLost`; behind a reset snapshot that lacks the element, at its catch-up). The wire and the room are unchanged. **And the other way** (round 2, L-4): a tab of the older web stays open for days and its store adopts every free-lock queue of the board and user whatever it holds, then sends it on a socket that names no revision (or saves it again without `rev`), so a current page's queued removal of the minutes would be completed as an older write and undone. The current web's IndexedDB records are therefore in a form the older store never matches (`boardId` `q2:<board>`, `offline-idb.ts` `queueBoard`); it still takes the older form over (an older page's queue is completed as above), and a Sign out in either web deletes both forms (by user). An adopted older create is forgotten as an older copy once its ack lands (it was written whole).
5. **The proof is the previous build's own parse, never a shim.** Each bump freezes the canvas-schema of the web that is deployed when it ships (`node scripts/freeze-protocol-fixture.mjs <commit> <rev> '<which web>'` writes `packages/canvas-schema/test/fixtures/rev<rev>-<commit>`; never edited; rev 11 is `rev11-437b4e7`) and proves the rule against it three ways: a diff of every vocabulary a server frame uses and a parse of each new data shape in every frame kind (`packages/canvas-schema/src/reader-rule.test.ts`: what the old parse ACCEPTS and DROPS, and that `frameForReader` makes all of it accepted and loses nothing); the real room with a client that parses with those schemas and names no revision (`apps/sync/test/element-room/stale-reader-rev11.test.ts`); and the browser pair with the real previous build (`e2e/excalidraw/l-compat-rev11.spec.ts`, run with `E2E_OLD_WEB_DIST`; how to build that dist: `e2e/excalidraw/l-compat-kit.ts`). Wave L's W6 stale-pair tests ran the current core behind a rev-11 shim and missed the hold: a shim does not check what the old build checks.

## 1. Rules for porting a feature (wave 3)

1. **Both engines keep working until wave 4.** The default build (no `VITE_LOBBY_ENGINE`) is today's tldraw app and keeps passing its e2e suite. So a feature is ported **beside** its tldraw code, not over it:
   - ported code lives in `…/<feature>/ported/**` (the folders of §7.2, created at wave 1 with an empty `CanvasFeature`);
   - the tldraw files stay as they are. A shared pure module (a model, an api client, a formatter) may be edited by its feature's owner only if both builds and both suites still pass; a type-only tldraw import in it (`TLShapeId`) may become `string`;
   - wave 4 deletes the tldraw files and moves `ported/**` up.
2. **Imports.** Ported code reaches the canvas only through `apps/web/src/canvas/api/index.ts` and uses `lib/signals.ts` for reactive state. It never imports `tldraw`, `@tldraw/*` or `@excalidraw/*`, and never another `canvas/**` module. Biome enforces it (`biome.json`, override `apps/web/src/**/ported/**`), and so does `canvas/api/contracts.test.ts`.
3. **`ctx.editor` becomes `ctx.canvas`.** A feature exports a `CanvasFeature` (§4) from its `ported/index.tsx`; `features/canvas-registry.ts` already imports it. tldraw's `overrides`, `components`, `options` and `Overlay` become registry declarations (§3).
4. **Writes** go through `ctx.canvas.transact(label, fn)`: one undo step, pushed by the sync engine. A `transact` whose callback throws applies nothing (tldraw's `bailToMark`). Board settings go through `canvas.doc.set` (lb_doc). Nothing else writes the canvas.
5. **Reads are reactive.** Every `LobbyCanvas` read called inside `useValue`, `computed` or `react` re-runs when it may have changed (the implementation tracks a signal source per concern). Port `useValue('x', () => editor.getSelectedShapeIds(), [editor])` to `useValue('x', () => canvas.selection, [canvas])`.
6. **One page, scene coordinates, element ids.** tldraw pages, parent spaces and `shape:` ids are gone from canvas code: every element's `x`, `y` are scene coordinates; frames hold children through `frameId`; groups through `groupIds`; a note's text is its bound label. api object refs stay `shape:<id>` (canvas-schema `refs.ts`); `SINGLE_PAGE_ID` fills a contract that still carries a page id.
7. **Plain text through the lease.** `canvas.text.edit` opens the editor only after the server grants the lease; programmatic words go through `canvas.text.replace` (existing elements) or `create` props `text` (new ones). No rich text.
8. **Keys, menus, tools** are declared (commands with `kbd`, `FeatureKeySpec`, `FeatureToolSpec`, menu entries); the keyboard-map test (3a) reads `collectKeyClaims(CANVAS_FEATURES)` and fails on `keyConflicts`. Only the key allowlist (2C, `canvas/input/`) dispatches keys.
9. **Identity and permissions stay server-side.** `readOnly()` and role checks are UI hints; the server refuses writes. Identity-bearing `customData` keys (`plusOne:<uid>`, `ai`, `privateFrame`) are stamped or checked by the server (canvas-schema `custom-data.ts`). A new `customData.lobby` key or `lb_doc` key is a change request to canvas-schema.
10. **Stubs throw.** A member whose owner has not landed it throws `NotImplementedError(owner, member)`. Call it anyway where the feature needs it (the feature is then done when the owner lands the member), or ask the owner for an early version; never work around a stub by reaching into the engine.
11. **Specs** are ported to `e2e/excalidraw/<feature>-<topic>.spec.ts` with the helpers of §9; the tldraw specs stay until wave 4. Overlays carry `data-lobby-*` or `data-testid` attributes.

## 2. `LobbyCanvas` (`canvas/api/lobby-canvas.ts`)

### 2.1 What it adds to the C0 port

`LobbyCanvas extends CanvasPort` (C0): the C0 members keep their meaning (`items`, `get`, `bounds`, `selection`, `select`, `viewport.get/set/fit`, `sceneToScreen`, `screenToScene`, `transact`, `setTool`, `tool`, `on`, `editingId`, `leaseHolder`, `collaborators`, `saveStatus`, `engine`). Added:

- **Mode, DOM, keyboard:** `readOnly`, `container`, `focus`, `hasKeyboard`, `setCursor`, `theme`.
- **Pointer and hit testing:** `pointer` (scene and screen point, modifiers, over-canvas, button down), `gesture` (`idle`, `dragging`, `editing-text`, …), `hitTest(point, {margin, hitInside, selectedFirst, skipLocked, filter})`, `hovered`.
- **Reads:** `boundsOf(ids?)`, `visibleBounds(id)` (clipped by its frame), `isLocked`, `isHidden`, `hide(owner, ids)` (the render side of a mind-map collapse), `sceneToOverlay` / `overlayToScene` (overlay-root pixels).
- **`viewport`** (widened): `zoomTo`, `centerOn`, `ensureVisible`, `zoomStep`, `stop`, `moving`, `limits`, `screenRect`, `remeasure`; `set` and `fit` take `{animate, force}`.
- **`transact(label, fn, {joinPrevious})`** with **`LobbyTx`**: `createMany`, `reorder`, `setFrame`, `group`, `ungroup`, `bind`, `duplicate` and (since W3-9) `insert` besides C0's `create`, `update`, `delete`.
- **Namespaces:** `text` (`of`, `canEdit`, `edit`, `stop`, `editorElement`, `measure`, `replace`), `styles` (`next`, `setNext`, `of`, `apply`; values in the engine's field names), `presence` (`peers`, `peer`), `follow` (`current`, `start` with its optional camera rule since W3-10, `stop`), `history` (`undo`, `redo`, `canUndo`, `canRedo`), `doc` (`get`, `entries`, `set`), `export` (`svg`, `png`, `canvas`, `copy`), `files` (`urlOf`, `status`, `insert`), `settings` (`get`, `set`).
- **Events** (`on`): `change` (created/updated/deleted with source `local`, `history` or `remote`), `input` (capture-phase pointer/wheel/key events with `handled()`), `toolChanged`, `editingChanged`, `resize`, `docChanged`, `followChanged`, besides C0's `changed`, `selectionChanged`, `viewportChanged`, `pointer`.

### 2.2 Who implements what

The board page (2C) builds the canvas with `createLobbyCanvas({port, registries, board})` (`canvas/api/impl.ts`; `board` is the page's engine handles, `canvas/board/handles.ts`). The C0 members delegate to the port, the reads are reactive (a signal source per concern), and 18 members are composed from port members alone (wave 1's seven plus 2C's `text.of`, `visibleBounds`, `sceneToOverlay`, `overlayToScene`, the six structural `tx` writes of `canvas/board/tx.ts` and the `transact` option `skipUndo`). 2C's other members are the board page's (status `board`): real when the page passes its `board` handles, a stub naming 2C on a bare port (as in the unit tests). Every member of a wave-3 owner was a stub naming its owner until the owner landed its part (W1-2). Since the wave-3 integration (W3-1) a landed part is listed in `LANDED_PARTS` (status `part`: real on any canvas, 3a's styles, 3b's camera members, 3c's follow, 3g's files) or, when it needs the board page's engine, in `LANDED_BOARD_PARTS` (status `board-part`: real on the board page, a stub naming its owner on a bare port, 3e's exports). The table is generated from `LOBBY_CANVAS_MEMBERS`; the contracts test fails when the object, the table and the `@owner` annotations in `lobby-canvas.ts` disagree.

The members owned by wave-3 owners are built in their own module under `canvas/api/parts/` and spread into the canvas by `impl.ts`: `navigation.ts` (3b: `viewport.zoomTo`, `centerOn`, `ensureVisible`, `zoomStep`, `limits`), `styles.ts` (3a: `styles.of`, `styles.apply`), `follow.ts` (3c: `follow.*`, `on('followChanged')`), `export.ts` (3e: `export.*`), `files.ts` (3g: `files.urlOf`, `files.insert`). ## 5. Signals and helpers

- **`lib/signals.ts`** replaces tldraw's `atom`, `computed`, `react`, `transact`, `useValue` and `unsafe__withoutCapture` (→ `untracked`) with the same shapes, plus `source` (a value-less signal adapters track and bump) and `subscribeValue`. Computeds are lazy and cached; effects run once per batch and not when a computed keeps its value; an effect that writes what it read re-runs, and a runaway loop throws after 1,000 rounds; an unobserved computed holds no reference from its dependencies. 9 unit tests.
- **`canvas/api/geometry.ts`** replaces `Box`, `Vec`, `Mat`: `rect`, `center`, `union`, `fromPoints`, `expand`, `translate`, `containsPoint`, `containsRect`, `intersects`, `intersection`, `distance`, `sameRect`, `corners` (rotated like Excalidraw).
- **`canvas/api/items.ts`** replaces shape types and parent chains: `itemKindOf` (note, text, label, shape, arrow, line, draw, highlight, image, file-card, frame), `labelOf`, `containerOf`, `textOf`, `arrowsOf`, `arrowEnds`, `childrenOf`, `outerGroupOf`, `groupMembers`, `contentItems`, `lobbyValue`, `lobbyEntries`.
- **`canvas/api/keys.ts`**: chords (`'mod+shift+f'`, `'alt+1'`, `'shift+f10'`), `matchChord` (letters and digits on `code`, so Alt+1 on a Mac and non-Latin layouts match; exact modifier sets), `formatChord` per platform.
